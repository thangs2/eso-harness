**Mục đích:** đặt Harness settings vào đúng tầng trước khi thiết kế UI.

## 1. L0 — Vì sao có Harness settings

| Nguồn | Điều nói |
|---|---|
| **P1** | Không phải host nào cũng có harness; cần harness của sản phẩm chạy trên host không có harness native |
| **P2** | Harness phải đủ mạnh cho hệ lớn; graph/memory không đủ thì trả lời sai |
| **P3** | Mỗi dự án có knowledge base/cấu hình riêng; không được hardcode một layout |
| **P4** | Câu hỏi bản sắc: đủ kiến thức để thực thi chưa, không chỉ đủ lượt đọc |
| **Mission** | Route → Collect → Score/Gate → Report |
| **Vision** | Chứng minh bằng evidence đã ghi, không tin lời agent |

Suy ra:

> Harness settings không phải trang “chọn provider”.
> Nó là nơi **lắp ghép và gán một harness stack** cho các host profile, để mỗi turn có đúng nguồn và đúng bằng chứng.

## 2. L1 — Landscape 5 tầng áp vào Harness settings

Landscape nền có 5 tầng: `SURFACE · KNOWLEDGE · PROVIDER · ESO · HOST`.

| Tầng | Trong Harness settings | Không thuộc |
|---|---|---|
| **SURFACE** | Cockpit cấu hình stack/profile; đọc/ghi qua một đường | không quyết định verdict |
| **KNOWLEDGE** | Stack layers: rules/law · skills · hooks · material | không chứa code host |
| **PROVIDER** | market · eso-native · host-native; memory/code graph/document graph | không giả vờ đủ |
| **ESO** | Observatory/gate/evidence; document graph là USP | không sở hữu agent loop |
| **HOST** | Cursor · AGY · Claude · Codex · DSH · Paseo · Orca; agent loop | host không phải consumer field |

```text
HOST (agent loop)
  ↑ projection / plugin
SURFACE (settings) ──▶ KNOWLEDGE (stack) ──▶ PROVIDER (sources)
  │                                            │
  └────────── ESO (gate/evidence) ◀────────────┘
```

### 4.1 Ownership / orchestration

```text
ESO SoT                 Host SoT
.harness/               .cursor/   (Cursor)
AGENTS.md (block)       .agents/   (AGY)
agents/ (marker)        .claude/   (Claude)
platform DB             host MCP config
```

| Plane | Orchestrator | Không phải |
|---|---|---|
| agent loop | host / Paseo / Orca | ESO CP |
| harness projection | ESO harness adapter | host |
| verdict/evidence | ESO CP | host |

**Federated SoT:** mỗi fact có một owner. Không có một folder làm SoT cho tất cả.

Host adapter contract:

```text
detect(root) -> host descriptor
project(material) -> only marked files/blocks
discoverMcp() -> read-only providers
capabilities() -> managed | detected | unknown
```

Unknown host = no-op, không error, host vẫn chạy.

## 5. L4 — Data model

```text
Consumer 1 ─── 1 HarnessStack 1 ─── * StackLayer
HarnessStack 1 ─── * HostProfile
HostProfile * ─── 1 HostPlugin
HostProfile * ─── * SourceBinding
StackLayer 1 ─── * MaterialSet
HostProfile 1 ─── * PluginBinding
Consumer 1 ─── * IntegrationBinding
```

### Bất biến

1. Stack là canonical; profile chỉ trỏ + override.
2. Host không phải field consumer.
3. Không có product tier/edition.
4. Không hardcode host/provider; registry từ plugin.
5. `docgraph` = document graph.
6. MCP config là máy-local: `mcp.json`, `mcp_config.json`, hoặc plugin.
7. Người dùng tự chọn host/stack/provider; không có combo bắt buộc.

## 7. L6 — Flows

### Tạo stack

```text
Chọn layer defaults
→ gán material
→ chọn source default cho memory/code graph
→ cấu hình document graph
→ publish stack v1
```

### Thêm host profile

```text
Chọn host plugin
→ chọn user/dev
→ gán stack version
→ override layer (nếu muốn)
→ khai MCP config source
→ install/project
```

### Đổi source

```text
Sửa profile override
→ preview affected layers
→ save
→ host sync
```

### Bật Jira

```text
jira.enabled
→ document graph config
→ SDLC Jira sync
→ manifest document
```
