# 13 — Unified Reconciliation Cockpit (Code ↔ Artifacts/SDLC/Rules ↔ PostgreSQL)

**Ngày:** 2026-11-26 · **Phiên bản:** `2.0.0` · **Tham chiếu luật pipeline:** [`01.main-pipeline.md`](../02.governance/04.diagrams/01.main-pipeline.md) & [`10.main-pipeline-rule.md`](../02.governance/01.standard/10.main-pipeline-rule.md).

Tài liệu này chuẩn hóa kiến trúc **Unified 3-Pillar Reconciliation Cockpit** — chốt chặn hòa giải ngược và đồng bộ trạng thái giữa 3 trụ cột **Source Code**, **Artifacts / SDLC / Rules / Skills (`*.md`)**, và **PostgreSQL Knowledge Index (`knowledge_doc`)** trên ESO Control Plane (`/consumers/:id/reconciliation`).

---

## 1. Bối cảnh & Bài toán (Bất đối xứng vận tốc Code vs Spec)

Trong quy trình SDLC chuẩn ([`01.main-pipeline.md`](../02.governance/04.diagrams/01.main-pipeline.md)), mọi tính năng đi xuôi qua 17 bước `S1…S17`:

```text
S1–S7 (Inception & Requirements) → CHK1 → S8–S10 (Technical Design) → S11–S13 (WBS/BIP/SCN) → CHK3/CHK2 → S14 (Code) → S15–S17 (Test/DoD/Human Sign-off)
```

Khi lập trình viên hoặc AI Agent thực hiện **Vibe Coding** (nhảy thẳng vào **`S14`** để sinh code nhanh trong 10–30 giây), hệ thống phát sinh đồng thời **3 lớp lỗ hổng**:

1. **Code ↔ Spec Drift (Lỗ hổng ngược):** Route/Schema/Spike hoặc thay đổi mã nguồn không có hợp đồng hay SHA-256 khóa biên.
2. **Missing SDLC Stage Docs (Lỗ hổng thượng nguồn):** Các file `*.md` bắt buộc từ `S1…S13` (`BRD`, `PRD`, `FRD`, `SRS`, `US/AC`, `API`, `Data`, `Arch/NFR`, `WBS`, `BIP/FIP`, `SCN/RTM`) bị bỏ trống.
3. **Disk ↔ PostgreSQL Index Drift (Lỗ hổng đồng bộ DB):** File `*.md` có trên đĩa nhưng chưa được index vào bảng `knowledge_doc` của PostgreSQL, hoặc `content_hash` trong DB cũ hơn đĩa, hoặc còn dòng rác (ghost row) từ file đã xóa.

Nếu không hòa giải, hệ thống rơi vào 3 bệnh lý: **Rationale Void** (mất vĩnh viễn lý do "Why"), **Agent Self-Poisoning** (AI đọc RAG/manifest cũ rồi sinh code xung đột), và **Cargo-Cult Documentation** (tài liệu hình thức lệch pha với thực tế).

## 2. Kiến trúc Hai Tốc Độ (Two-Speed SDLC)

| Tiêu chí | Làn 1: Vibe / Spike (Thực nghiệm) | Làn 2: Canonical / Mainline (Sản phẩm) |
|---|---|---|
| **Môi trường** | Branch tạm (`spike/*`, `feat/vibe-*`), Local Worktree | Branch chính (`main`), Release Tags |
| **Quy trình** | Code trước, thử nghiệm nhanh | Bắt buộc Spec-Driven, đóng băng SHA-256 Manifest |
| **Kết thúc bằng** | **Hòa giải trên Reconciliation Cockpit** | **Gate S17 Sign-off** → đồng bộ Disk + Manifest + PostgreSQL |

## 3. Kiến trúc Hợp nhất 3 Trụ cột (Unified 3-Pillar Architecture)

```text
┌───────────────────────────┐     ┌──────────────────────────────────┐     ┌──────────────────────────────┐
│  PILLAR 1: SOURCE CODE    │     │  PILLAR 2: ARTIFACTS · SDLC      │     │  PILLAR 3: POSTGRESQL DB     │
│  AST · Routes · Schemas   │ ◄─► │  sdlc/ (S1–S17) · rules · skills │ ◄─► │  platform.knowledge_doc      │
│  GAP-A · GAP-B · GAP-D    │     │  GAP-C · GAP-E                   │     │  GAP-F                       │
└───────────────────────────┘     └──────────────────────────────────┘     └──────────────────────────────┘
```

### 3.1. Ma trận chuẩn 6 nhóm GAP (`GAP-A` → `GAP-F`)

| Mã GAP | Tên danh mục | Trụ cột | Dấu hiệu phát hiện (Deterministic Scanner) | Đích chuẩn (Canonical Target theo `01.main-pipeline.md`) | Hành động chính trên Cockpit |
|---|---|---|---|---|---|
| **`GAP-A`** | **Orphan Routes** | Source Code | Route/endpoint (`@Get`, `@Post`, `app.get`, `router.post`...) trong code chưa được khai báo trong spec | `sdlc/07.technical/03.api/<slug>.api.md` *(đối chiếu S7 `sdlc/06.analysis/02.ac/`)* | **Extract Draft to Inbox** |
| **`GAP-B`** | **Unfed Schemas** | Source Code | Model/table (`.prisma`, `*ddl*.ts`, `*.sql`, `*.entity.ts`) chưa có trong Data Dictionary | `sdlc/07.technical/02.data-design/03.data-dictionary.md` | **Extract Draft to Inbox** |
| **`GAP-C`** | **Stale Contracts** | Artifacts / SDLC | File được quản trị (`sdlc/`, `agents/rules/`, `agents/skills/`, `agents/subagents/`) có SHA-256 trên đĩa lệch với `.harness/knowledge-manifest.json` | `.harness/knowledge-manifest.json` | **Re-verify & Re-lock Hash** *(+ tự re-index Postgres)* |
| **`GAP-D`** | **Unlinked Spikes** | Source Code | File `.md` trong `artifacts/` chưa được tham chiếu trong `sdlc/` hoặc manifest | `sdlc/03.inception/02.decision-log/<slug>.md` | **Extract Draft to Inbox** |
| **`GAP-E`** | **Missing SDLC Docs** | Artifacts / SDLC | Stage bắt buộc trong Master Pipeline `S1–S13` (`Problem`, `Vision`, `BRD`, `PRD`, `FRD`, `SRS`, `AC`, `API`, `Data`, `Arch`, `WBS`, `BIP/FIP`, `SCN`) có `0` file `.md` trên đĩa | Thư mục chuẩn từng stage trong [`01.main-pipeline.md`](../02.governance/04.diagrams/01.main-pipeline.md) §3 | **Generate Skeleton to Inbox** *(đủ YAML frontmatter chuẩn `KM-05`)* |
| **`GAP-F`** | **Postgres Index Drift** | PostgreSQL DB | So sánh mọi `*.md` trên đĩa vs `knowledge_doc` trong PostgreSQL: `unindexed` (chưa có trong DB), `stale` (`content_hash` lệch), `ghost` (file đã xóa trên đĩa) | `platform.knowledge_doc` (PostgreSQL) | **Sync PostgreSQL Index** |

> Mọi GAP ở trạng thái `open` đều hỗ trợ thêm 2 hành động phụ: **Copy Agent Prompt** (prompt chuẩn kèm đường dẫn + code snippet + Lead Role `PO/BA/TECH/PM/QC`) và **Dismiss** (ghi vào `.harness/reconcile-ignore.json`).

## 4. Ba Bất biến Chống "Vibe Documentation" (Gate S17 Invariants)

1. **Invariant I-01 — Never Auto-Approve:** Nút *Extract Draft* / *Generate Skeleton* tuyệt đối không ghi thẳng vào `sdlc/` hay tự duyệt.
2. **Invariant I-02 — Staging Mandate:** Mọi bản nháp sinh từ Reconciliation phải đi vào **Artifacts Inbox** với `origin: 'agent'`, `metadata.originType: 'reverse-extraction'`, và `ktState: 'proposed'`, kèm đoạn `codeSnippet` trích xuất thật từ file nguồn (hoặc khung YAML frontmatter cho `GAP-E`).
3. **Invariant I-03 — Human Rationale & Atomic Sync (Gate S17):** Con người review bản nháp trong Artifacts Inbox, bổ sung Rationale ("Why" & Trade-offs), rồi bấm **Promote to KB**:
   - Backend kiểm tra an toàn đường dẫn (chặn path traversal, chỉ cho phép ghi dưới `sdlc/`).
   - Ghi file `.md` xuống đích chuẩn, cập nhật SHA-256 vào `.harness/knowledge-manifest.json`.
   - Tự động gọi `KnowledgeIndexService.index(consumerId)` để đồng bộ PostgreSQL và chuyển trạng thái GAP sang `resolved`.

## 5. Đặc tả Backend Engine & HTTP API

Triển khai tại:
- Engine: `eso/control-plane/src/modules/knowledge/reconciliation-scanner.service.ts`
- Promotion: `eso/control-plane/src/modules/knowledge/artifact-lifecycle.service.ts`
- Routes: `eso/control-plane/src/common/http/server.ts` (toàn bộ đi qua `requireAuth`)
- Tests: `eso/control-plane/test/reconciliation-scanner.test.ts`

| Method & Endpoint | Chức năng | Ghi chú kỹ thuật |
|---|---|---|
| `POST /api/v1/consumers/:id/reconciliation/scan` | Chạy quét thật `consumer.root` + đối chiếu PostgreSQL | Body `{ scope?: 'full' \| 'git-diff' }`. Chế độ `git-diff` chỉ quét các file thay đổi/untracked từ `git status --porcelain` & `git diff --name-only HEAD`. Tự lọc nhiễu mặc định (`/health`, `/healthz`, `/metrics`, `_prisma_migrations`, `schema_migrations`) và `.harness/reconcile-ignore.json`. |
| `GET /api/v1/consumers/:id/reconciliation/gaps` | Lấy kết quả quét gần nhất (hoặc tự chạy scan lần đầu) | Trả về `{ consumerId, scannedAt, scope, ignoredCount, postgresStats, pipelineStages, gaps }` đã đồng bộ trạng thái `open / staged_in_inbox / resolved` từ bảng artifacts. |
| `POST /api/v1/consumers/:id/reconciliation/ignore` | Lưu GAP vào danh sách loại trừ | Ghi atomic vào `<consumer.root>/.harness/reconcile-ignore.json`. |
| `POST /api/v1/consumers/:id/reconciliation/relock` | Băm lại SHA-256 & khóa lại manifest cho `GAP-C` | Chặn path traversal, cập nhật `.harness/knowledge-manifest.json`, tự động gọi `knowledgeIndex.index()`, đánh dấu GAP `resolved`. |
| `POST /api/v1/consumers/:id/reconciliation/sync-index` | Đồng bộ toàn bộ `*.md` trên đĩa vào PostgreSQL | Chạy `knowledgeIndex.index(id)` rồi trả về kết quả `scan()` mới nhất để xóa sạch `GAP-F`. |

### 6.2. Quy ước Thị giác Bắt buộc (Visual Language)

1. **Zero OS Emoji:** 100% biểu tượng dùng monochrome inline SVG (`stroke-width: 1.5`–`1.6`, kế thừa `currentColor`).
2. **Dark-Slate Tiết chế:** Chỉ dùng `--surface`, `--surface-2`, viền hairline `1px solid var(--line)`, số đếm `font-variant-numeric: tabular-nums`, duy nhất 1 màu nhấn `--brand` cho action chính & mục đang chọn.
3. **4 Cột Phase `S1–S17` (`.stage-col`):** Dùng `border-left: 3px solid` phân biệt 4 nhóm giai đoạn của `01.main-pipeline.md` với 4 trục màu tách biệt rõ ràng trên nền tối:
   - `stage-col-a` (Requirements `S1–S7`): `#3b82f6` (Blue)
   - `stage-col-b` (Technical `S8–S10`): `#fb923c` (Orange)
   - `stage-col-c` (Breakdown `S11–S13`): `#10b981` (Emerald)
   - `stage-col-d` (Delivery `S14–S17`): `#a855f7` (Purple)
   - Các `.stage-chip` bên trong giữ nền neutral `--surface-2` kèm chấm trạng thái `6px` (`#10b981` covered · `#f59e0b` drift · `#ef4444` missing).
4. **Master-Detail Workbench:** Cột trái hiển thị danh sách dạng hàng gọn (quét mắt nhanh hàng chục GAP cùng lúc), cột phải là Inspector bám dính (`position: sticky`) hiển thị đầy đủ ngữ cảnh & nút xử lý.
5. **Responsive & A11y:** Không tràn ngang ở `360px / 768px / 1440px`, `:focus-visible` rõ nét, tôn trọng `prefers-reduced-motion`, 0 lỗi/cảnh báo DevTools console.

## 7. Mục còn Mở (OPEN / Future Enhancements)

- **CLI Pre-PR Gate:** Chưa có lệnh `eso reconcile --check` chạy trong CI/pre-PR hook (hiện thao tác qua HTTP API & Control Plane UI).
- **Deep AST Extractor cho GAP-A / GAP-B:** Scanner hiện dùng regex/pattern matcher có giới hạn phạm vi file; nâng cấp tương lai có thể đọc trực tiếp symbol graph từ `Codegraph` để giảm false-negative trên các framework file-based routing (như Next.js App Router).
