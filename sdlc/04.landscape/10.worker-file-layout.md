# 10 — Worker files: canonical, placement, projection

**Câu hỏi:** Register worker + host binding thì lưu ra file nào, ở đâu?

## 1. Hiện tại

Register worker **chưa sinh file worker**. Nó nằm trong settings profile:

```text
settings.harness.workers[]
  id · name · role · layer · scope · hostBindingIds[] · status
settings.harness.formationHostIds[]
settings.harness.workerEdges[]
```

`.harness/config.json` là artifact materialized từ profile. Chưa có `agents/subagents/<worker>.md`.

## 2. Nguyên tắc

```text
worker definition  = host-neutral, canonical
host binding       = runtime placement, consumer-specific
projection         = generated cho từng host, không sửa tay
```

Không nhét host binding vào worker file. Nếu nhét:

```text
7 worker × 3 host = 21 bản definition
```

Sai. Chỉ có **7 definition + 21 placement**.

## 8. Projection

Generate:

```text
agents/subagents/scout-runtime.md
  → .cursor/agents/scout-runtime.md
  → .agents/agents/scout-runtime.md
```

Host nào không hỗ trợ subagent thì không sinh file đó.

Không sinh host binding vào projection. Binding đọc từ `.harness/bindings/`.

## 9. Source of truth

Đề xuất:

```text
agents/subagents/*.md     = worker definition
.harness/bindings/*.json  = host binding
.harness/placements.json  = worker × binding
.harness/formation.json   = edges
.harness/config.json      = consumer metadata + pointers
.cursor/** .agents/**      = generated, không sửa tay
```

Nếu giữ DB là source (BR-03) thì `.harness/config.json` materialize toàn bộ; nhưng worker **file** vẫn là projection, không phải nơi nhập tay.

## 9b. Quyết định B — canonical worker files

Operator chốt **2026-11-12**:

```text
B — worker definition canonical ở agents/subagents/*.md
```

Điều này có nghĩa:

```text
agents/subagents/<worker>.md   = nguồn worker definition
.harness/bindings/*.json       = host binding
.harness/placements.json       = worker × binding
.harness/formation.json        = edge
.harness/config.json           = metadata + trỏ tới các file trên
DB                             = index/query, không phải nơi nhập worker
```

### Hệ quả với BR-03

BR-03 hiện nói **DB là nguồn** cho profile, `.harness/config.json` là artifact.

Worker definition là **agent material**, không phải consumer profile metadata. Vì vậy cần đọc BR-03
theo hướng:

```text
profile metadata (name/root/sdlcRoot/general/settings):
  DB source → .harness/config.json generated

worker definition:
  agents/subagents/*.md source → DB index generated
```

Không được để cả hai cùng là source cho một worker. Nếu giữ nguyên BR-03 cho toàn bộ settings thì B
không đứng được, và UI Register worker đang làm sai (chỉ ghi JSON).

### Pipeline khi implement B

```text
1. UI Register worker
2. server validate role/layer/scope
3. ghi agents/subagents/<worker>.md
4. parse lại file → worker index
5. cập nhật placements/formation
6. sinh .cursor/agents + .agents/agents
7. cập nhật DB index
8. UI đọc index
```
