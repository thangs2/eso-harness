# Knowledge & Artifact Governance — re-analysis

**Ngày:** 2026-11-11 · **Nguồn:** operator review tab `Jira` + artifact model hiện có.

Tài liệu này chốt **tab tiếp theo làm gì**, vì sao `Jira` không phải tab core, và knowledge base /
document graph / SDLC / provider khác nhau ở đâu.

Không đặc tả API. Không thay thế artifact model; bổ sung góc nhìn.

## 2. Bốn khái niệm không được gộp

| Khái niệm | Full name | Là gì | Không phải |
|---|---|---|---|
| Knowledge base | **Consumer Knowledge Base** | Tập artifact + metadata + trạng thái tri thức | Graph index |
| Document graph | **Document Relationship Index** | Index quan hệ giữa docs/artifacts/code/external refs | Nơi lưu nội dung |
| SDLC | **SDLC Artifact Contract** | Template/phase/role/CR tùy chọn | Product tier |
| Provider | **Knowledge / Work Provider** | Jira · Notion · Confluence · Figma · GitHub | Core dependency |

```text
Knowledge base = WHAT knowledge exists
Document graph = HOW knowledge is related
SDLC           = WHICH artifact contract applies
Provider       = WHERE some knowledge/task is stored
```

## 3. Jira là provider, không phải tab

```text
Jira       → task management provider
Notion     → document/knowledge provider
Confluence → document provider
Figma      → design provider
GitHub     → code/review provider
```

Nếu consumer không dùng Jira:

```text
task artifact → repo file
task provider → none
```

Nếu dùng Jira:

```text
task artifact → Jira issue
Jira = SoT cho kind đó
ESO giữ link/reference, không copy nội dung
```

Luật giữ nguyên:

- mỗi `kind` có đúng **một** SoT
- provider active phải khai kind nó giữ
- sync một chiều: SoT → bản sao
- không sync hai chiều

## 4. SDLC là optional

### Không dùng SDLC

```text
sdlc.enabled = false
```

Kết quả:

- không tạo `sdlc/`
- không bắt buộc BRD/PRD/FRD/SRS
- không phase gate
- knowledge base vẫn hoạt động
- document graph vẫn index docs

Ví dụ:

```text
README.md
docs/architecture.md
docs/decisions.md
```

### Dùng SDLC

```text
sdlc.enabled = true
```

Kết quả:

- tạo `sdlc/`
- áp artifact contract
- có phase / role / template
- có CR process nếu bật
- gate theo template

**Không gọi Lite/Pro/Enterprise.** Đây là loại dự án, không phải hạng sản phẩm.

Mô hình:

## 6. Artifact representation: human / agent / machine

Artifact model hiện có 6 facet:

```text
kind · origin · custodian · liveness · kt-state · owner
```

Bổ sung chiều:

```text
representation: human | agent | machine
```

| Representation | Ai đọc | Ví dụ | SoT |
|---|---|---|---|
| `human` | người | BRD, PRD, README, ADR, report | thường có |
| `agent` | host/agent | AGENTS.md, host-generated context, skill notes | thường derived |
| `machine` | tool/manifest | manifest.json, index, refs, config | thường derived |

```text
origin ≠ representation
```

Ví dụ:

```text
AGY tự tạo tài liệu để xử lý
  origin = agent
  representation = agent
  custodian = repo/plugin
  kt-state = raw
```

```text
Người viết BRD, Jira giữ issue
  origin = human
  representation = human
  custodian = provider
  kt-state = approved
```

```text
Test sinh manifest
  origin = machine
  representation = machine
  custodian = provider
```

Quan hệ bắt buộc:

```text
machine/agent representation derived_from human source
derived ⊆ source
```

Không chép nội dung.

## 7. Knowledge base vs document graph

### Knowledge base

```text
artifact tồn tại
kind
owner
representation
custodian
kt-state
liveness
```

### Document graph

```text
artifact A liên quan artifact B
doc reference doc
doc thuộc phase nào
doc link task/provider
```

```text
KB = content + metadata
Docgraph = edges + provenance
```

Nếu SDLC off:

```text
docgraph index docs/** + README + ADR
không yêu cầu artifact kind SDLC
```

Nếu SDLC on:

```text
docgraph index sdlc/** + phase artifacts + CR links
```

## 10.4 Task hierarchy — quartet chưa đủ

Standard quartet chỉ đủ cho **một implementation slice**:

```text
tdd-unit · tdd-impl · tdd-coverage · tdd-qc
```

Nó **không** đủ cho quản lý công việc cấp epic/feature.

Cần hierarchy:

```text
Epic / Feature
├── Story
│   └── Subtask: fe · be · qa · qc · pm
├── Task
│   └── Subtask
└── Bug
```

Quy tắc:

| Cấp | Dùng quartet? |
|---|---|
| Epic / Feature / Story / Task | **không** — chỉ container |
| Implementation subtask | **có** — standard quartet |
| Runtime slice | extended + load/stress |
| Bug | không bắt buộc quartet |
| BA | OUT khi AC đã rõ |

Kết luận: quartet là **subtask taxonomy**, không phải toàn bộ task model.

## 10.5 WBS artifacts — đang thiếu

Knowledge base phải có:

| Artifact | Nội dung |
|---|---|
| **WBS** | deliverable tree · 100% rule · không thiếu/thừa |
| **WBS dictionary** | scope · owner · acceptance · dependency cho từng node |
| **Atomic WBS** | leaf work package; leaf sở hữu `AC`; không orphan |

WBS **phải có trước** BIP/FIP packet. Leaf không có `AC` ⇒ WBS sai.

## 10.6 DoR và DoD

Cả hai phải hiện trong pipeline detail.

| | DoR | DoD |
|---|---|---|
| Câu hỏi | được phép **bắt đầu** chưa? | đã **xong** chưa? |
| Chốt | lúc tạo ticket · lúc vào sprint | lúc chuyển `Done` |
| Fail | Backlog + label `needs-dor` | vẫn `In Progress` + lý do |
| Ai chốt | người tạo ticket | **chỉ người** |

DoR conditions:

1. 4 relations declared
2. packet §9 = `READY`
3. work package đủ 7 fields
4. AC trích từ SoT
5. một dòng verify
6. dependency có tên

DoR áp cho `Story` và `Task`; không áp `Epic` (container), `Subtask` (inherit),
`Bug` (phải reproducible).

DoR **không phải Jira status**; nó là gate + label `needs-dor`.

## 10.9 Agent manifest — standard cho consumer

> **Sửa 2026-11-12 sau operator review:** `sdlc/01.agent-manifests` chỉ là **sample để study**.
> Không được lấy 8 domain / 10 capability / 54 US refs của eso-harness làm nội dung config của testeso.

Manifest là **machine-readable contract** để AI hiểu cấu trúc tài liệu mà không crawl cây.

### Manifest contract

```text
identity
  consumer_id · root · manifest_version

documents[]
  path · id · kind · status · owner · representation

kinds[]
  required header keys · required sections · owner

relations[]
  derived_from · source_of_truth · human_sot
  blocks · owns_kinds · references

paths
  relative locator; path không phải identity
```

### Facets

```text
kind · origin · custodian · liveness · kt-state · owner · representation
```

### Header keys

```text
sot_doc_version · status · source_of_truth · phase · id
type · human_sot · representation · owner
```

### Checks

```text
links resolve
header shape
derived ⊆ source
no orphan document
kind has owner
```


Đây là **contract** cho testeso. Không phải danh sách domain/capability của eso-harness.
