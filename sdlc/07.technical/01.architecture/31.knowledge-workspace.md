# 31 — Knowledge workspace

## Decision

Knowledge settings is a **workspace**, not one long configuration page.

```text
header      current state + actions
sub-tabs    Overview · Sources · Contract · Index & health · Manifest
body        one selected section
footer      save / cancel
```

Knowledge sub-tabs are page-local, below the Settings tab strip.

## Sections

| Section | Question it answers | Content |
|---|---|---|
| Overview | What is the state now? | Summary cards, preflight, source routing |
| Sources | Where does knowledge come from? | Knowledge base, document graph, provider routing, external references |
| Contract | What must be true? | Project mode, governance checks, task quartet |
| Manifest | What is the machine contract? | Manifest keys/facets/relations/checks + emitted shape |
| Index & health | Is the derived index usable? | Manifest/build stats, documents, findings, retrieval, coverage |

## Why

Before the re-layout the page mixed:

```text
index operations
document table
governance controls
task decomposition
manifest internals
provider routing
side detail
```

into one vertical scroll. The same concept appeared in the top panel
and the side panel; actions were repeated; a first-time reader could not
tell whether the page was about **policy**, **index health**, or **files**.

After:

```text
one page = one knowledge surface
sections are ordered, not hidden behind tab strips
provider routing is a source decision, not a footnote
manifest is its own machine-contract surface
```

## Manifest subtab

The Manifest subtab is an **editor + live contract preview**, not a duplicate chip list.

```text
left   emit toggle · path · grouped controls with selected counts
right  contract reference · emitted shape (JSON built from current signals)
```

Rules:

```text
INV-M1  stats are computed from selections, never hardcoded
INV-M2  right column shows derived JSON, not the same chip lists again
INV-M3  path is relative to consumer root and generated
INV-M4  toggling a chip updates count + preview immediately
INV-M5  manifest preview never uses an inner scroll box
INV-C1  contract detail uses page scroll; no max-height/overflow trap
```

## Rules

```text
INV-KW1  Files are source; index/graph/manifest are derived
INV-KW2  Providers are optional; no provider = .md
INV-KW3  Overview never edits; it reports and routes
INV-KW4  Index & health never changes source files
INV-KW5  Manifest controls only the machine-readable contract
INV-KW6  Indexed documents show every row; no inner scroll box
```

## UI implementation

```text
section order     = Sources → Contract → Manifest → Index
detail aside      = selected contract/manifest reference
no tab visibility = all sections remain in the page
```
