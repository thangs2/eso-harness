# 36 — Prompt mode router: `mode=A|B` (host-side)

## 1. Vấn đề

Mode A/B là placement của worker, nhưng người dùng khởi đầu mọi việc bằng **prompt**. Nếu prompt
không chọn được mode thì UI/config-only là thiếu. Router này biến directive trong prompt thành
execution, **không phụ thuộc SLP**.

## 2. Hợp đồng prompt

```text
mode=A <task>
mode=B <task>
impl <KEY> slp g mode=A|B <task>   # SLP optional
```

- `mode` bắt buộc ở đầu prompt; phần còn lại là task.
- **Không** dùng `to=...`; target lấy từ `worker-placement`.
- Không có `mode=` ⇒ router không can thiệp.

## 3. Luồng

```text
prompt
 → parse mode + task
 → GET config-snapshot (host token, runtimeKey)
 → default flow → entry worker
 → worker-placement {modes, allowedHosts}
 → choose target (A local / B first remote)
 → host-runtime run (A) | dispatch (B)
 → observation cùng traceId
```

Không gọi ESO để execute; ESO chỉ đọc config.

## 4. Hành vi lỗi

| Tình huống | Kết quả |
|---|---|
| mode không bật trên worker | fail: `does not enable mode B` |
| mode B nhưng không remote host | fail: `no allowed remote` |
| không có default flow | fail: `no default flow configured` |
| prompt có `to=` | fail: `to= is not allowed` |
| thiếu task | fail: `mode directive needs a task` |

Fail-closed, không fallback sang chat/SLP.

## 5. Cài đặt

- `scripts/slp-mode-router.mjs` — parser + resolver + executor.
- `setup-consumer-hosts.mjs` cài `.harness/hooks/eso-mode-router.mjs` + `esoRoot` vào `.harness/eso-host.json`.
- Skill `agents/skills/mode-router/SKILL.md` hướng dẫn host chạy router khi prompt bắt đầu `mode=`.

## 6. Hiện trạng

| Phần | Trạng thái |
|---|---|
| Parser / target resolver | DONE, unit test |
| Dry-run plan | DONE (`--dry-run`) |
| Mode A execute | DONE qua `host-runtime run` |
| Mode B execute | DONE qua `host-runtime dispatch`; cần remote server + token |
| Hard hook intercept | **chưa**; hiện là skill instruction (model-followed) |

Muốn deterministic 100%, bước tiếp theo là PreInvocation hook gọi router và inject kết quả.
