# 24 — Retrieval: graph + FTS + vector

**Câu hỏi:** có nên dùng vector DB riêng để tìm tài liệu/memory/code gần nghĩa, và có thể tốt hơn AgentMemory không?

**Chốt 2026-11-14:** không cài vector DB riêng ở giai đoạn này. Dùng **PostgreSQL + pgvector** làm vector engine,
nhưng thắng/thua không nằm ở vector — nằm ở **hybrid retrieval**.

## 1. AgentMemory đang làm gì

Theo README package `@agentmemory/agentmemory`:

```text
BM25 keyword search
+ vector embedding (optional)
+ knowledge graph
+ RRF fusion
```

Keyless mode:

```text
không vector
memory_recall = BM25
memory_smart_search = BM25 + graph nếu có
```

Semantic mode:

```text
EMBEDDING_PROVIDER=local
Xenova/all-MiniLM-L6-v2
hoặc remote embedding provider
```

Ngoài retrieval, AgentMemory còn:

```text
automatic capture
compression
4-tier consolidation
decay
contradiction
versioning
scoping
provenance
```

Benchmark họ công bố là **BM25 component**, không phải toàn bộ hybrid:

```text
LongMemEval-S top 5
strict recall-all@5 = 84.7%
any-hit@5 = 96.2%
không dùng embedding/API
```

## 2. Vector một mình không thắng AgentMemory

Nếu ESO chỉ thêm:

```text
embedding + vector index
```

thì vẫn thiếu:

```text
BM25/FTS
RRF fusion
graph expansion/filter
scope filter
dedupe
provenance
decay/consolidation
evaluation
```

Kết quả có thể **tệ hơn** AgentMemory keyless.

## 3. ESO có lợi thế riêng

ESO có thứ AgentMemory không có:

```text
document graph có provenance
code graph có symbol/edge
knowledge doc_id/section_id ổn định
source_of_truth/human_sot
worker/formation/handoff
per-consumer scope
```

Nếu giữ được các tín hiệu đó trong retrieval, ESO có thể **tốt hơn cho project knowledge/code**,
không nhất thiết hơn cho session memory.

## 4. Ba lựa chọn

| | A. Không vector | B. Postgres pgvector | C. Vector DB riêng |
|---|---|---|---|
| Semantic recall | kém | có | có |
| Graph/FTS join | tốt | tốt | khó |
| Ops | thấp | thấp | cao |
| Cost | thấp | trung bình | cao |
| Lock-in | không | thấp | cao |
| Phù hợp hiện tại | nếu không cần semantic | **chọn** | chưa |

## 5. Chốt

```text
1. Không cài vector DB riêng.
2. pgvector trong Postgres là vector engine.
3. Retrieval = FTS + vector + graph + RRF + filter.
4. Vector là optional mode, không phải dependency của graph.
5. AgentMemory giữ vai trò session memory.
6. ESO làm project knowledge/code/memory retrieval.
```

## 6. Kiến trúc retrieval

```text
query
  ├─ FTS (tsvector)
  ├─ vector (pgvector)
  ├─ graph candidates (edges)
  └─ structured filters (scope/type/status/worker)
        ↓
      RRF
        ↓
      top-k
        ↓
   rerank/filter
        ↓
   evidence + provenance
```

Không:

```text
vector similarity → tạo edge
vector similarity → thay source_of_truth
```

## 7. Embedding model

Chưa chốt model. Tiêu chí:

```text

cost/latency
```

Schema hiện tại:

```text

```

Nếu dùng local 384/768 chiều:

```text
đổi dimension hoặc bảng riêng
không trộn model trong cùng cột
```

## 11. Vector worker chờ quyết định gì — cụ thể

Không phải chờ “làm vector”. Chờ **5 thông số**.

### 11.1 Model

Phải chọn một `model_id` cụ thể:

| Model | Dim | Chạy | Tiếng Việt | Chi phí | Schema |
|---|---:|---|---|---|---|
| `text-embedding-3-small` | 1536 | API | khá | token API | phải đổi cột |
| `text-embedding-3-large` | 3072 | API | tốt | token API | phải đổi cột |
| `paraphrase-multilingual-MiniLM-L12-v2` | 384 | local | có | 0 API | phải đổi cột |
| `BAAI/bge-m3` | 1024 | local | tốt | 0 API | phải đổi cột |
| `nomic-embed-text-v1.5` | 768 | local | yếu hơn | 0 API | phải đổi cột |
| `all-MiniLM-L6-v2` | 384 | local | yếu | 0 API | AgentMemory đang dùng |

### 11.2 Runtime

```text
API provider      → cần key + network + cost
local ONNX        → cần @huggingface/transformers + model download
local service     → cần process/model server
```

### 11.3 Dimension

Cột hiện tại:

```sql
embedding vector(1024)
```

Nếu model khác 1024:

```text
ALTER TABLE knowledge_doc_chunk
  ALTER COLUMN embedding TYPE vector(384/768/1024)
```

hoặc tạo bảng mới + reindex. Không trộn dimension.

### 11.4 Chunk policy

```text
chunk_size       # token/ký tự
overlap
theo section hay theo cửa sổ
có embed heading không
```

### 11.5 Evaluation

Phải chốt trước khi tuyên bố “tốt hơn”:

```text
bộ câu hỏi
recall@5
strict recall-all@5
MRR
latency
```

## 13. Đề xuất

Nếu ưu tiên tiếng Việt + offline:

```text
BAAI/bge-m3 · 1024 · local
```

Nếu ưu tiên triển khai nhanh, chấp nhận API:

```text
text-embedding-3-small · 1536 · API
```

Chưa chốt thì vector worker **không nên chạy**, vì đổi model là phải re-embed toàn bộ.

## 14. Local vector implementation 2026-11-14

```text
model      BAAI/bge-m3
runtime    @huggingface/transformers (Xenova/bge-m3, q8)
dimension  1024
schema     knowledge_doc_chunk.embedding vector(1024)
index      HNSW vector_cosine_ops
```

Pipeline:

```text
POST /knowledge/index
  → knowledge_doc_chunk (22 chunks từ 9 docs)
POST /knowledge/embed
  → local embed 8 chunk/batch
  → update embedding

POST /knowledge/retrieve
  → FTS + graph + vector
  → RRF
```

Đo:

```text
chunks            22
embedded          22
embed time        ~5.6s (cache model)
query             "agent instruction"
FTS 2 · graph 0 · vector 9 · merged 9
top               agents/instructions.md  fts · vector · title
```

Lưu ý:

```text
index lại thì chunk cũ bị xoá
→ phải Embed pending lại
```

Muốn giữ embedding qua reindex:

```text
chunk content_hash
+ upsert chunk không đổi
+ giữ embedding
```
