# 29 — Plugin-able management

## Scope

Phase D separates:

```text
installed ≠ enabled ≠ selected
```

```text
/plugins                    system registry
/consumers/:id/plugins      consumer activation + config
Host binding                provider selection
Stack                       allowed sources/policy
```

## Built-in catalog

```text
host      cursor · agy · claude · dsh · paseo
provider  jira · notion · confluence
```

Host adapters are read-only on the consumer page; they are tied to host bindings.

## Data

```text
platform.consumer_plugin
  consumer_id · plugin_id · enabled · config jsonb
  secret_refs jsonb · health · last_checked_at · updated_at
  primary key (consumer_id, plugin_id)
```

Built-in manifests live in backend code for this slice. Custom plugin
installation is not implemented.

## API

```text
GET  /plugins
GET  /consumers/:id/plugins
PUT  /consumers/:id/plugins/:pluginId
POST /consumers/:id/plugins/:pluginId/test
```

Config payload:

```json
{
  "enabled": true,
  "config": {
    "baseUrl": "https://company.atlassian.net",
    "projectKey": "ESO",
    "authMode": "api-token",
    "syncMode": "manual"
  },
  "secretRefs": {
    "apiToken": "env:JIRA_API_TOKEN"
  }
}
```

Secrets are references only:

```text
env:NAME · secret:path · vault:path
```

Never store plaintext token in `config`.

## Jira example

```text
Base URL       https://company.atlassian.net
Project key    ESO
Auth mode      api-token
Sync mode      manual
API token      env:JIRA_API_TOKEN
```

`test` validates config and returns:

```text
configured
```

It does **not** claim network health; real ping/sync is a later slice.

## UI

System:

```text
/plugins
  installed/available cards
  type · version · capabilities · status
```

Consumer providers page:

```text
/consumers/:id/plugins
  summary     providers · enabled · healthy · host adapters
  left        provider groups only (hosts excluded)
  right       lifecycle: installed → enabled → configured → healthy
              schema-driven fields
              Save · Test connection · Sync now
              no record table on the provider page
              plugin id / source / capabilities
```

Hosts are explicitly out of the provider page; they are managed by Host bindings.

## Navigation boundary

Settings has **no Plugins tab**. Provider management is a first-class consumer page:

```text
/consumers/:id/plugins
```

Old URL:

```text
/consumers/:id/settings?tab=plugins
  → redirect
/consumers/:id/plugins
```

This prevents a second, partial plugin registry inside Settings.

## Classification

Every plugin has `category`:

```text
host
work
design
content
other
```

UI groups by category:

```text
Hosts
Work management
Design management
Content management
```

Provider routing selects per area:

```text
work     → jira
design   → figma · penpot
content  → notion · confluence
```

## Custom plugin

```text
POST   /plugins
DELETE /plugins/:pluginId
```

Custom provider can declare:

```json
{
  "connector": {
    "kind": "http-json",
    "healthPath": "/health",
    "recordsPath": "/records",
    "idField": "id",
    "titleField": "title",
    "kindField": "kind"
  }
}
```

## Provider data boundary

Synced records are **not** shown on the provider page at all.
They feed the Knowledge external-reference index; provider configuration
stays focused on connection, project scope, test, and sync.

Jira project scope is optional and discovered from the tenant:

```text
GET /consumers/:id/plugins/jira/projects
  → BAPlatform · BAP
  → eso · ESO
  → x79 · X79
```

Empty scope syncs `updated >= -30d` across accessible projects.

```text
platform.provider_record
  consumer_id · provider_id · external_id · kind
  title · status · url · payload · synced_at
```

## Legacy Jira migration

When a consumer has no `consumer_plugin(jira)` row, `PluginService.consumer()`
reads legacy `.harness/config.json`:

```text
settings.knowledge.providers.jira
```

and creates:

```text
consumer_plugin(jira)
  enabled = legacy.enabled
  config.projectKey = legacy.projectKey
  health = unconfigured
```

The old UI fields are no longer the editing surface.

## Live integration check

Jira is verified against a real tenant:

```text
health  /rest/api/3/myself       200
sync    /rest/api/3/search/jql   50 issues
token   env:JIRA_API_TOKEN
```

The provider page shows real issue keys, kinds, statuses and links.

## Not implemented

```text
marketplace / plugin signature / sandbox
OAuth flows
background scheduled sync (sync is manual)
provider push/write-back
```

## Invariants

```text
INV-P1  provider config belongs to consumer_plugin, not .harness
INV-P2  secret values are references, not config values
INV-P3  host adapter config is not editable here
INV-P4  enabled provider still requires Stack/binding selection to be used
```
