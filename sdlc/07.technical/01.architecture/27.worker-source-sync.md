# Worker source sync and SLP proposals

## Ownership

```text
agents/subagents/*.md       worker identity source
agents/rules/*slp*.mdc       SLP intent source
.harness/flows/*.json       flow source
.agents/agents/*.md         projection
.cursor/agents/*.md         projection
```

One source per artifact. The same fact is never read from two places.

## Direct IDE edits

Canonical edits:

```text
edit agents/subagents/*.md
  → Sync sources
  → worker index rebuilt
  → flow unchanged
```

Projection edits:

```text
edit .agents/agents/*.md
  → drift detected
  → Promote to source, or discard
```

Promote is one-way: projection → canonical. It never runs automatically.

## SLP flow proposal

Structured SLP block:

````markdown
```slp-flow
{
  "id": "slp-proposal",
  "name": "SLP Proposal",
  "edges": [
    { "from": "worker-scout", "to": "worker-plan", "on": "PASS" }
  ]
}
```
````

API:

```text
GET  /consumers/:id/slp/flow-proposal
POST /consumers/:id/slp/flow-proposal/apply
```

Rules:

- prose is never parsed as a flow
- proposal creates a draft only
- human validates and publishes
- existing published flow is never overwritten

## Why not two-way sync

Two-way sync recreates the formation split-brain:

```text
agents/subagents ↔ .agents/agents
```

Projection is generated; source is canonical. Direction is fixed.
