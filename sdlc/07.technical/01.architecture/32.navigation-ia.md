# 32 — Navigation information architecture

## Decision

One application sidebar. No horizontal top tabs, no consumer sub-tabs,
no settings tabs.

```text
header      brand + account only
sidebar     one navigation tree
content     one page header + one page body
```

## Sidebar groups

```text
Workspace
  Consumers
  Work overview
  Diagnosis

Consumer · <id>          (only inside a consumer route)
  Overview
  Settings
  Flows
  Providers
  Work

Governance
  Declaration
  Risk
  Audit

System
  Registry
```

Settings is one page with one horizontal tab strip:

```text
Profile · Stack · Host Bindings · Agent Workers · Knowledge · Observatory
```

Tabs are URL-backed (`?tab=`) and remain in the page content. They are not
sidebar children.

## Work overview

`/work-overview?project=<id>` keeps the consumer in the sidebar context.
The consumer `Work` item is active, not the global Work overview item.

## Knowledge

Knowledge sits under the Settings tab strip and has its own requested
sub-tabs:

```text
Overview · Sources · Contract · Index & health · Manifest
```

```text
Overview      summary cards · preflight · current source routing
Sources       knowledge base · document graph · provider routing · external refs
Contract      project mode · governance · task quartet
Index         manifest stats · documents · findings · retrieval · coverage
Manifest      manifest contract · emitted shape
```

These are page-local tabs, not sidebar entries.

## Header consistency

Every routed page uses one header contract:

```text
min-height  96px
alignment   flex-start
padding     app content padding only
```

Flows uses `page-header flows-head`; other pages use `page-header`.
`eso-content` is the only page padding owner; pages do not add their own
outer padding or max-width.

## URL state

```text
/consumers/:id
/consumers/:id/settings?tab=profile|stack|hosts|workers|knowledge|observation
/consumers/:id/flows
/consumers/:id/plugins
/work-overview?project=<id>
/plugins
```

Settings URL changes update the active section via query params. The sidebar
settings child links drive those URLs.

## Redirects

```text
/settings?tab=plugins  → /consumers/:id/plugins
/login?returnUrl=...   → internal return URL
/projects              → /consumers
unknown                → /consumers
```

## Rules

```text
INV-NAV1  one sidebar navigation tree
INV-NAV2  no global top tabs; Settings and Knowledge are local tab strips
INV-NAV3  no consumer sub-tab strip in content
INV-NAV4  Settings tabs stay in content, not in the sidebar
INV-NAV5  every page header min 96px
INV-NAV6  pages do not double-pad or max-width inside eso-content
INV-NAV7  no dead menu target
```

## Responsive

```text
desktop   sidebar fixed; settings tabs 6 equal columns
tablet    sidebar fixed; settings tabs 3 columns
mobile    sidebar hidden behind menu button; drawer overlay
          settings tabs 2 columns
          consumer table becomes stacked cards
```

## Verified

```text
all page headers       96px desktop
sidebar active states  correct
settings tabs          6 honest labels, URL-backed
knowledge sub-tabs     restored
mobile drawer          open/close PASS
mobile 360             no horizontal overflow
console errors         0
```
