# 28 — Flow configuration and observation

## Rule

```text
ESO = sidecar / control plane / observatory
ESO ≠ runtime
```

ESO owns **flow configuration and observation**. It does **not** own run or execution.

```text
Flow JSON      config: nodes + outcome edges
Host session   owns execution + conversation
Host           sends observation/evidence
ESO            stores and displays
```

There is no:

```text
Run button
run request
run queue
claim
advance
flow run state machine
worker run state machine
```

## Flow editor

```text
draft → validate → publish → default pointer
```

Published flow is immutable. `.harness/flows/` remains the flow source of truth.

## Observation

Where the host reports activity, ESO stores generic **observations/evidence**, not an ESO run.

Allowed model:

```text
trace_id
worker_id
event
host_id
outcome
evidence
timestamp
```

Forbidden model:

```text
flow_run
flow_step
run_id
claim
advance
```

No observation endpoint is defined yet. When added, it must be host-reported activity only, never an ESO
start/queue/claim/advance surface.

## API

Flow configuration only:

```text
GET/PUT /consumers/:id/flows/:flowId
POST    /consumers/:id/flows/:flowId/validate
POST    /consumers/:id/flows/:flowId/publish
GET/PUT /consumers/:id/flows/default
```

No flow-run API exists.

## Boundaries

```text
not start run
not execute worker
not queue work
not claim work
not advance flow
not spawn host
not chat
not call model
```

Those belong to the host. See
[33.host-registry-and-placement.md](33.host-registry-and-placement.md).
