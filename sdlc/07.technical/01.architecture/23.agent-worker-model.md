# 23 — Agent worker model

**Câu hỏi:** “permission enforcement” cho agent workers là gì — có phải IAM identity/role/policy không?

**Trả lời:** Không. Đây là **agent worker identity + role + scope + bar + handoff**, không phải
user IAM.

## 1. Khác IAM ở đâu

| | IAM | Agent worker |
|---|---|---|
| Principal | user/service account | worker do operator khai |
| Authn | password/token/session | không có credential |
| Role | quyền hệ thống | capability nghề + layer |
| Policy | grant/deny trên resource | scope ghi/đọc + bar bằng chứng |
| Lifecycle | active/disabled | declared/active/paused/retired |
| Enforcement | DB/API/RLS | trước khi spawn, trước khi ghi, trước handoff |
| Nguồn | DB IAM | file `agents/subagents/*.md` + index |

Không xây login/tenant/RLS cho worker. Worker không có mật khẩu.

## 2. Mô hình

```text
Worker
  id
  name
  status: declared | active | paused | retired
  role
  layer: peer | gate
  capabilities[]        # nghề mở: be, fe, qc, design, pm, review…
  verbs[]               # đóng: read, write, append, approve, configure, handoff
  scope[]               # path/tool được đọc/ghi
  bar[]                 # bằng chứng bắt buộc trước khi ghi
  escalation            # allow | stop+notify | run+warn+notify
```

Placement tách riêng:

```text
worker × host binding
```

Handoff tách riêng:

```text
from worker → to worker · on condition
```

Handoff edges lấy từ **default published flow** (`.harness/flows/index.json`).
Worker file không chứa edges.

## 3. Ví dụ

```yaml
id: worker-qc
name: QC
role: qc
layer: gate
status: active
capabilities: [qc, review]
verbs: [read, append]
scope:
  - /tmp/slp/qc/
bar:
  - scenario executed
  - evidence captured
escalation: stop+notify
```

Build worker:

```yaml
id: worker-build
role: build
layer: peer
capabilities: [be, fe]
verbs: [read, write, append]
scope:
  - slice.allowed_files
bar:
  - tests added
  - verify command
```

## 4. Điểm cưỡng chế

```text
1. resolve worker từ file/index
2. worker status = active?
3. host placement + stack version hợp lệ?
4. spawn/turn mang worker_id
5. pre-write: path/tool nằm trong scope + verb?
6. gate/handoff: bar đủ?
7. evidence ghi worker_id + role + scope + verb
8. status paused/retired ⇒ không nhận việc mới
```

Không có bước nào là login.

## 5. DB index

Implemented:

```text
knowledge_worker              worker identity + policy
knowledge_worker_placement    worker × host binding
knowledge_worker_edge         default flow edge index
knowledge_worker_event        policy check/write/spawn/handoff events
knowledge_worker_handoff      accepted/rejected handoffs
knowledge_worker_run          spawned worker runs
knowledge_worker_import       import audit
```

`knowledge_worker` carries:

```text
worker_id · name · role · layer · scope · status
file_path · content_hash
host_binding_ids · capabilities · verbs · bar · escalation
```

`knowledge_worker_edge` is derived from the default published flow. It is not
a second flow source.

## 6. File canonical

`agents/subagents/<worker>.md`:

```yaml
---
id: worker-qc
name: QC
role: qc
layer: gate
status: active
capabilities: [qc, review]
verbs: [read, append]
scope: /tmp/slp/qc/
bar:
  - kind: scenario
    metric: executed
    op: truthy
    value: true
escalation: stop+notify
---
```

Parser reads:

```text
id · name · role · layer · status · scope
capabilities · verbs · bar · escalation
source_file · source_hash · source_type
```

Worker file never contains:

```text
host binding
flow edges
flow version
```

## 7. Hiện trạng

```text
worker file store              DONE
worker DB index                DONE
placement                      DONE
default flow edge index        DONE
status transition              DONE
typed evidence policy          DONE
scope/verb/bar enforcement     DONE
gate write-scope enforcement   DONE
worker policy check API        DONE
handoff with evidence          DONE
spawn identity (optional)      DONE
worker event / run / handoff   DONE
worker import + audit          DONE
flow source / default pointer  DONE
worker source sync + drift     DONE
SLP flow proposal              DONE
flow runtime Phase C           CHƯA
```

Enforcement order:

```text
worker file → index
→ status active
→ scope + verb
→ gate write scope
→ typed evidence bar
→ handoff edge + condition
```

## 8. Kết luận

```text
permission enforcement = worker policy enforcement
không phải IAM identity/roles
không bị block bởi IAM
```

Việc tiếp theo:

```text
1. thêm capabilities/verbs/bar/escalation vào file
2. parse và index
3. thêm scope rules + role version
4. pre-write checker
5. evidence worker_id
```

## 9. Identity states — FULL / DECLARED / DEGRADED

Từ [`08.actor-domain-tenant`](08.actor-domain-tenant.md):

```text
FULL       host cung cấp role → scope/bar/chain đầy đủ
DECLARED   role do ESO khai trong file; không xác minh người thực thi
DEGRADED   không biết role → không được kết luận sufficient
```

Worker B là **DECLARED**.

## 10. Một worker — một role

Theo [`12.worker`](../02.data-design/12.worker.md):

```text
worker.project · worker.worker_id · role_name · harness_source · state
```

Không FK tới `role`:

```text
role nâng version → worker vẫn là worker đó
```

Kiểm ở app:

```text
UNKNOWN_ROLE nếu role_name không có version current|superseded
```

Policy phải pin version:

```text
policy.subjects[] = { role_name, role_version }
```

Vì `role@7` đổi `bar` mà policy không đổi byte ⇒ cùng turn hai phán quyết.

## 11. Bang giao ba trục

```text
scope  deny-overrides     lớp nào cấm thì cấm
bar    max-required       vai đòi cao nhất là chuẩn
chain  min-across-chain   chặng yếu nhất quyết định
```

Không dùng một luật chung cho cả ba.

## 12. State machine

```text
declared ──▶ active ──▶ paused
                 │          │
                 └──────────┴──▶ retired
```

Luật:

```text
paused: không nhận việc mới, việc đang giữ vẫn còn
retired: không xoá; việc dở thành risk OPEN có owner
một worker không đổi project tại chỗ
```

## 13. Gap matrix

| Hạng mục | Hiện tại | Cần |
|---|---|---|
| `capabilities[]` | không có | file + DB |
| `verbs[]` | không có | file + DB, đóng |
| `bar[]` | không có | file + DB |
| `scope` | một string | rule `(verb, kind, value)` |
| `escalation` | không có | file + DB |
| `role_version` | không có | policy pin |
| worker events | không có | append-only |
| pre-write checker | không có | runtime |
| host identity | declared | FULL nếu host cấp |
| evidence worker_id | không có | evidence turn |

## 14. Kết luận

```text
Agent worker ≠ IAM user
Agent worker = declared agent identity + role policy + placement + handoff
Permission enforcement = kiểm worker policy tại pre-write / handoff / spawn
Không cần IAM để làm worker policy
```


## 15. Implementation 2026-11-14

Đã thêm:

```text
file frontmatter
  capabilities[] · verbs[] · bar[] · escalation

knowledge_worker columns
  capabilities text[] · verbs text[] · bar jsonb · escalation text

API
  POST /consumers/:id/workers/:workerId/check
```

Test:

```text
build worker
  scope /tmp/slp/build/
  verbs read,write,append
  bar tests added
  status active

check write /tmp/slp/build/file.ts + evidence "tests added"
  ALLOW

check write /tmp/slp/other/file.ts
  DENY PATH_OUTSIDE_SCOPE

qc gate write
  DENY VERB_NOT_ALLOWED + GATE_WORKER_CANNOT_MUTATE
```

Vẫn chưa làm:

```text
spawn identity
evidence worker_id
handoff bar enforcement
UI check action
```


## 16. Runtime enforcement 2026-11-14

Đã nối policy vào control-plane:

```text
POST /workers/:id/check     → check + event
POST /workers/:id/write     → check + ghi file + event
POST /workers/:id/spawn     → status + placement + event
POST /workers/:id/handoff   → edge + target bar + event
GET  /workers/:id/events    → evidence trail
```

Bảng:

```text
knowledge_worker_event
  event_id · worker_id · event · verb · path
  · decision · reasons · evidence · created_at
```

Test:

```text
write agents/policy-probe.md + tests added
  ALLOW, file written

write sdlc/policy-probe.md
  DENY PATH_OUTSIDE_SCOPE

spawn hb-missing
  DENY PLACEMENT_MISSING

handoff to qc no evidence
  DENY BAR_MISSING:scenario executed

events
  worker-build-write · write · ALLOW
  worker-build-write · spawn · DENY
  worker-build-write · handoff · DENY
```

UI:

```text
Worker row → Check
→ verb / path / evidence
→ ALLOW | DENY + reasons
```

Lưu ý:

```text
write path nằm trong consumer root
spawn là authorization, chưa spawn process thật
handoff chưa chuyển work object
```


## 17. Handoff object + spawn process 2026-11-14

### Handoff object

```text
knowledge_worker_handoff
  handoff_id · from_worker_id · to_worker_id · condition
  · status pending|accepted|rejected
  · work jsonb · evidence jsonb · created_at · accepted_at
```

API:

```text
POST /workers/:id/handoff            { toWorkerId, evidence, work }
POST /workers/:id/handoffs/:id/accept
GET  /workers/:id/handoffs
```

Test:

```text
handoff build → qc + work { slice: "S1" }
  ALLOW ho-...
accept as qc
  ACCEPTED, work preserved
```

### Spawn process

```text
knowledge_worker_run
  run_id · worker_id · host_binding_id · status
  · pid · command · started_at · ended_at
```

Adapter:

```text
ESO_WORKER_SPAWN_COMMAND
ESO_WORKER_SPAWN_ARGS
```

Không có command:

```text
status = authorized
```

Có command:

```text
Bun.spawn
→ status spawned + pid
→ exit → exited | failed
```

Test:

```text
spawn hb-test
  spawned pid 84240
  /bin/sleep 2
→ runs: exited
```
