# `21` — Harness domain model + logical schema

## 1. Ubiquitous language

| Thuật ngữ | Nghĩa | Không phải |
|---|---|---|
| **Harness stack** | Stack 8 layer canonical của consumer | một source chain |
| **Stack layer** | Một tầng trong stack | plugin |
| **Material** | Bộ file/folder rules/skills/hooks/subagents | source provider |
| **Multi-agent policy** | Roles → workers → permissions → workflows | file material |
| **Source binding** | Layer memory/code-graph lấy từ đâu | host field |
| **Host profile** | Cặp `(user, host plugin)` được gán stack | consumer |
| **Plugin** | Host adapter, provider, MCP, worker, hook | host enum |
| **MCP config** | Config máy-local hoặc plugin | stack layer |
| **Document graph** | USP ESO: `doc → section → id` | docgraph search tool |
| **Jira bundle** | Document graph + SDLC sync + manifest | bắt buộc |

`docgraph` = **document graph**. Không dùng hai nghĩa.

## 2. L2 — Bounded contexts

```text
CONSUMER / REPO
├── STACK (canonical) ◀── HOST PROFILE (user × host plugin)
│     └── LAYERS ──▶ MATERIAL
├── PLUGIN REGISTRY
├── DOCUMENT GRAPH
└── INTEGRATION (MCP · Jira)
```

| Context | Sở hữu | Không sở hữu |
|---|---|---|
| **Stack** | layer selection, version, status | host install state |
| **Layer** | config shape từng layer | provider runtime |
| **Material** | file refs, hash, kind | project code |
| **Multi-agent** | roles, workers, permissions, workflows | host agent loop |
| **Source binding** | memory/code-graph source choice | plugin implementation |
| **Host profile** | user × host × stack assignment | consumer identity |
| **Plugin registry** | installed plugins, capabilities, config schema | stack semantics |
| **Document graph** | index config, Postgres refs, manifest | market search |
| **Integration** | MCP source, Jira enable/sync | credentials plaintext |

## 3. Aggregates

### 3.1 `HarnessStack`

```text
HarnessStack
  id
  consumerId
  version
  status           draft | published | superseded
  layers           8 layer objects
  createdAt
  publishedAt
  hash
```

Bất biến:

1. Một consumer có nhiều version; chỉ một `published` tại một thời điểm.
2. Published stack immutable.
3. Stack không chứa host, path máy, secret.
4. Stack không chứa MCP config máy-local.

### 3.2 `HostProfile`

```text
HostProfile
  id
  consumerId
  userId
  hostPluginId
  stackRef         { stackId, version }
  overrides        layer overrides
  pluginBindings   provider/MCP refs
  mcpConfigRef
  installState     pending | installed | partial | error
  createdAt
  updatedAt
```

Bất biến:

1. Profile trỏ stack published; không copy.
2. Profile không sửa stack.
3. `(userId, hostPluginId)` duy nhất trong consumer.
4. Override chỉ ở layer cho phép.
5. MCP config là ref; không copy nội dung.

### 3.3 `PluginRegistry`

```text
PluginManifest
  id
  type             host | source | provider | mcp | worker | hook
  version
  capabilities[]
  configSchema
  uiSchema
  projections[]
  secretRefs[]
  status           installed | enabled | disabled | error
```

Bất biến:

1. UI không hardcode host/provider list.
2. Plugin thiếu capability phải báo warning.
3. Plugin config schema là nguồn render form.

## 3.4 Stack ↔ HostProfile — relationship and ordering

Stack and HostProfile are **not peers** and neither owns the other.

```text
Consumer
├── HarnessStack      definition: what harness layers/sources are
└── HostProfile       binding: who uses which host, pinned to a stack version
```

| Question | Answer |
|---|---|
| Does a stack belong to a host? | **No.** Stack belongs to consumer. |
| Does a host profile belong to a stack? | **References** a stack version; not owned by it. |
| Must host exist before stack? | **No.** Stack can be defined with zero hosts. |
| Must stack exist before host profile? | **Yes**, or the profile is unbound. Create a draft/default first. |
| Can one stack serve many hosts? | **Yes.** |
| Can one host have many profiles? | **Yes**, one per user/profile. |
| Unknown tool? | No profile; no stack effect. |
| Delete host profile? | Stack remains unchanged. |
| Delete stack? | Published stack is immutable; profiles pin versions. |

### Order of concerns

```text
1. Consumer/repo
2. Stack definition (can be draft/default)
3. Host detection (observation; may happen before or after 2)
4. HostProfile binding (requires stack + host)
5. Projection
```

Detection is **not** a stack dependency. A host marker can exist before ESO; it becomes a profile only when
ESO is asked to manage it.

### Why Add host is not Stack

| Add host asks | Stack defines |
|---|---|
| which host | layer set |
| which user/developer | source defaults |
| which stack version | document graph config |
| optional overrides | canonical material |

Overrides are exceptions. If Add host repeats all stack fields, the UI duplicates the stack and the operator
cannot tell which value is canonical.

### 3.5 Stack policy vs Host resolution

Stack declares **policy/requirement**. HostBinding declares **resolution**.

| Fact | Owner |
|---|---|
| memory required / allowedSources | Stack |
| code graph required / allowedSources | Stack |
| document graph enabled/config | Stack (ESO-only) |
| material | Stack |
| memory source/provider per host | HostBinding |
| code graph source/provider per host | HostBinding |
| MCP config ref | HostBinding |

If Stack and Host both expose `source → provider`, the operator has two sources of truth.
That was the defect in the previous UI.

### 3.6 Stack versions

```text
HarnessStack
  versions: StackVersion[]

StackVersion
  version: integer
  status: draft | published | retired
  layers: HarnessLayer[]
  publishedAt?: string
```

HostBinding pins `stackVersion`.

Invariants:

1. Published version immutable.
2. New binding defaults to latest published.
3. Publishing a version never mutates existing bindings.
4. Upgrade/rollback is explicit.
5. Cannot delete a published version referenced by a binding.
6. Effective config resolves from pinned version only.

### 3.7 Persistence target — stack versions in Postgres (O-SH1)

Target: DB is SoT; settings JSON and `.harness` are projections.

```text
harness_stack
  id, consumer_id, created_at

harness_stack_version
  id, stack_id, version_number, status,
  layers_json, published_at, created_at

host_binding
  id, consumer_id, developer_id, host_runtime_id,
  stack_version_id, capability_bindings_json,
  mcp_config_ref, install_state, created_at
```

Rules:

- Published version immutable.
- Host binding references `stack_version_id`.
- Publishing never updates existing bindings.
- `settings.harness.stack` is a cache/projection, not the source of truth.

Current UI still persists versions in consumer settings JSON; this is the migration target.

## 5. Cardinality

```text
Consumer 1 ─── * HarnessStack
Consumer 1 ─── * HostProfile
HarnessStack 1 ─── 8 StackLayer
StackLayer 1 ─── 0..1 MaterialSet
StackLayer 1 ─── 0..1 SourceBinding
HostProfile * ─── 1 HarnessStack (published version)
HostProfile 1 ─── 1 PluginManifest (host)
HostProfile * ─── * PluginManifest (provider/MCP)
Consumer 0..1 ─── DocumentGraphConfig
Consumer 0..1 ─── JiraConfig
```

## 6. Invariants toàn cục

1. `stack` canonical; `profile` chỉ trỏ/override.
2. Host không phải field consumer.
3. Không có product tier/edition.
4. Không hardcode host/provider enum.
5. `none` hợp lệ; thiếu binding là invalid.
6. Plugin thiếu capability phải warning/fail-closed theo policy.
7. MCP config là ref máy-local/plugin; không copy.
8. Jira bật ⇒ document graph bật.
9. Document graph chỉ Postgres.
10. `docgraph` = document graph.
11. Người dùng tự do chọn host/stack/provider; không combo bắt buộc.
12. Published stack immutable.
13. Profile pin stack version; upgrade là hành động rõ ràng.

## 7. Storage — logical, chưa migration

| Entity | Store | Ghi chú |
|---|---|---|
| `HarnessStack` | control plane DB | canonical, versioned |
| `HostProfile` | control plane DB | assignment; projection state |
| `PluginRegistry` | control plane DB | installed/capability |
| `MaterialSet` | consumer repo + DB ref | file hash |
| `DocumentGraphConfig` | control plane DB | refs |
| `JiraConfig` | control plane DB | secret refs |
| `MCPConfigRef` | profile DB + machine file | không copy |

Không thêm bảng trước khi có migration plan.

## 8. Lifecycle

```text
stack.draft
  → publish (immutable version)
  → assign to host profiles
  → host sync/projection
  → new stack version
  → upgrade profiles
  → old stack superseded
```

Profile state:

```text
pending → installed | partial | error
```
