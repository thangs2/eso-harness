# 33 — Host registry and placement

## Rule

```text
ESO = config + sidecar + observatory + control plane
ESO ≠ runtime
```

ESO configures **where a host may execute**, but never executes. Execution and conversation belong to the
host session where the operator prompts:

```text
Cursor · AGY · Claude · Codex · DSH · Paseo · Orca
```

## Host registry

Global, shared by every consumer:

```text
platform.host_runtime
  host_id primary key
  runtime_id · runtime_kind
  models jsonb · default_model
  lead_eligible · health · last_heartbeat
```

`runtime_kind` is the transport surface, not the host brand:

```text
cli         one-shot process (cursor-agent -p, agy -p)
acp         persistent Agent Client Protocol stdio server (agy acp)
ide-native  interactive session only
```

Measured 2026-11-16:

```text
cursor-agent 2026.11.13  -p/models/persist/worker; no ACP command
agy 1.5.9                -p/models/acp; agy acp is ACP stdio
```

No workspace on host. Workspace is `platform.consumer.root`, owned by the consumer.

## API

```text
GET  /api/v1/host-runtimes
PUT  /api/v1/host-runtimes/:hostId
POST /api/v1/host-runtimes/:hostId/heartbeat
```

Host runtime reports:

```text
runtimeId · runtimeKind · models · defaultModel · leadEligible · health
```

Models are host-reported, never typed by ESO.

## Worker placement config

```text
knowledge_worker_host_policy
  worker_id
  allowed_hosts[]
  model_tier: fast | balanced | reasoning
  native_agent{hostId -> agent}
  fallback: block | next-host | next-tier
```

API:

```text
GET /consumers/:id/worker-placement
PUT /consumers/:id/workers/:workerId/execution
```

ESO only stores the policy. The host maps `model_tier` to a concrete model from its own catalog.

## Consumer binding

```text
Hosts                  global registry
Host Bindings          developer × registered hostId × Stack version
Worker placement       worker → allowed hostIds + model tier
Workspace              consumer root, not host
```

Host Bindings lists only global registered hosts. A binding to an unregistered/offline host is shown
unavailable.

## Host side (outside ESO)

The host session where the user prompts owns:

```text
prompt + conversation
flow evaluation
worker execution
model selection
CLI / ACP / native agent
workspace access
observation + evidence
```

Mode A/B are host-side properties, not ESO features:

```text
Mode A  same host / different model
Mode B  different host / different model
```

ESO neither starts nor dispatches them. It only provides config and displays observation.

## Forbidden in ESO

```text
run · execution · chat
flow_run · worker_run · run_id
start · queue · claim · advance
spawn process · call model · hold host credentials
```

## Gap

`hostId` currently doubles as host type in seed data. Multiple machines of one host type need an explicit
`hostType` field (Phase 2).

## 12. Mode A/B — analysis 2026-11-17

### 12.1 Current ESO capability

Available now:

```text
consumer root            GET consumer profile
flow config              GET /consumers/:id/flows/:flowId
worker identity/policy   GET /consumers/:id/workers
worker placement         GET /consumers/:id/worker-placement

stack versions           GET /consumers/:id/stack-versions
host bindings            consumer profile settings.harness.hostProfiles
provider routing         consumer profile settings.knowledge.providers.routing
```

Not in ESO:

```text
flow run
worker run
run queue
claim
advance
execution adapter
chat
```

### 12.2 ESO configuration gaps

| ID | Gap | Impact |
|---|---|---|
| G1 | No aggregate config snapshot endpoint | host must call 6+ APIs and join them itself |
| G2 | No read-only host principal/token | host must use operator token |
| G3 | No observation/evidence ingestion API | host activity cannot reach ESO; observatory is blind |
| G4 | `hostId` doubles as host type | multiple machines of the same host type collide |
| G5 | No model-tier mapping table | host must invent mapping per tier |
| G6 | No offline config snapshot/cache | host cannot work when ESO is down |
| G7 | No prompt/evidence contract | host cannot produce a stable observation schema |
| G8 | Host adapter does not exist | nothing executes SLP yet |
| G9 | No host-to-host transport | Mode B impossible |
| G10 | No workspace/artifact handoff contract | Mode B remote cannot exchange repo state |

Proposed read-only snapshot (no run/execution surface):

```http
GET /api/v1/consumers/:id/config-snapshot?hostId=...
```

```json
{
  "version": "etag-or-hash",
  "consumer": { "id": "testeso", "root": "/repo" },
  "flow": { "flowId": "that-tinh-tran", "version": 1, "nodes": [], "edges": [] },
  "workers": [],
  "workerExecution": [],
  "hosts": [],
  "hostBindings": [],
  "stackVersion": 1,
  "providerRouting": {}
}
```

This is config only. It does not start, queue, claim, or advance anything.

### 12.3 Host requirements

```text
user prompt + host session (Lead)

```

Mode B adds:

```text

```

### 12.4 Mode A — host reads config

```text
1. user prompts Cursor/AGY
2. host reads config snapshot
3. host picks worker + modelTier
4. host maps modelTier → host model catalog
5. same host executes:
   Cursor native subagent model
   or cursor-agent -p --model
   AGY agent/--model
   or agy -p --model
6. gate evidence
7. host evaluates flow internally
8. host sends observation/evidence to ESO
```

| Level | Description | Status |
|---|---|---|
| A0 | config only | available |
| A1 | Cursor native subagent model | host-side missing projection |
| A2 | AGY native/CLI model | host-side missing projection |
| A3 | deterministic per-worker CLI | host adapter missing |
| A4 | full evidence loop | observation ingestion missing |

Mode A gaps:

```text
A-G1 project modelTier/nativeAgent into .cursor/agents or AGY agents
A-G2 host execution adapter
A-G3 prompt/evidence contract
A-G4 observation ingestion

```

### 12.5 Mode B — host reads config

```text
2. host A reads config snapshot + global host registry
3. worker allowedHosts includes host B
4. host A dispatches to host B
   B1 same machine CLI
   B2 remote SSH + CLI
   B3 remote host runtime API/ACP
5. host B executes worker
6. host B returns outcome/evidence
7. host A evaluates flow internally
8. host A sends observation/evidence to ESO
```

Levels:

| Level | Description | Status |
|---|---|---|
| B0 | config only | available |
| B1 | same machine, different CLI | host-side missing |
| B2 | remote SSH + CLI | host-side missing |
| B3 | remote runtime API/ACP | host runtime missing |
| B4 | remote workspace/artifact full | contract missing |

Mode B gaps:

```text
B-G1 host-to-host transport
B-G2 remote auth
B-G3 workspace/ref/commit
B-G4 artifact handoff
B-G5 remote evidence schema

```

```text
1. config-snapshot read API          ESO
2. observation/evidence ingestion   ESO

```

### 12.8 Invariant

Nothing in this document gives ESO a run, execution, queue, claim, advance, chat, process, or model
surface. ESO remains sidecar/config/observatory. The host owns the prompt, execution, model choice,
workspace, and observation.

## 13. Second-pass review 2026-11-17

Plan is directionally correct, but **not yet the best solution**. Findings:

### 13.1 Literal law conflicts — resolved 2026-11-17

ESO config surfaces were renamed away from `execution`:

```text
knowledge_worker_host_policy
/worker-placement
PUT /consumers/:id/workers/:workerId/placement
WorkerPlacementDto
"Host placement" UI
```

`knowledge_index_run` was an index-build ledger, not agent execution; renamed to
`knowledge_index_build`.

Remaining framework/external names such as NestJS `ExecutionContext` and host hook
`beforeShellExecution` are not ESO execution concepts.

### 13.2 Host ↔ runtime cardinality

Current registry:

```text
platform.host_runtime(host_id PRIMARY KEY)
```

This assumes one runtime per host. A machine can have Cursor + AGY + DSH at the same time.

Target:

```text
platform.host
  host_id · host_type · machine identity

platform.host_runtime
  host_id · runtime_id · runtime_kind · models · default_model
  PRIMARY KEY (host_id, runtime_id)
```

Until this is fixed, `cursor`/`agy` as hostIds conflate machine and runtime.

### 13.3 Missing host entrypoint

The plan never defines **how user prompt activates SLP**. Config alone does nothing.

Need host-side entrypoint:

```text
Cursor: rule/hook/agent invocation
AGY: rule/agent/command
Claude/Codex/DSH/Paseo/Orca: equivalent
```

Without it, Mode A/B cannot start.

### 13.4 Flow semantics duplication

If every host reimplements edge evaluation, behavior drifts. Best:

```text
ESO publishes flow config
host uses shared pure flow library/package
ESO does not run it
```

### 13.5 Observation contract missing

Need:

```text
observation_id / idempotency key
host_id · runtime_id · worker_id
trace_id
event · outcome · evidence
timestamp
offline buffer + replay
append-only ingest
no run_id
```

No observation ingestion exists today.

### 13.6 Mode B is not safe with raw SSH

Preferred order:

```text
1. host-to-host job envelope + auth + workspace ref + evidence
2. runtime API/ACP
3. SSH/CLI fallback
4. raw GUI/shell not supported
```

Host A must not trust host B evidence blindly; need verification policy.

### 13.7 Model tier mapping

`model_tier` alone is not enough for reproducible quality. Host should report:

```text
tier_map: fast/balanced/reasoning → model + effort
```

ESO stores mapping as host-reported config; host resolves.

### 13.8 Config source coherence

Avoid two sources:

```text
ESO config-snapshot
.harness projection
```

Best:

```text
canonical files → ESO derives snapshot + hash
host reads snapshot/hash
offline cache = last snapshot
```

### 13.9 Revised priority

```text
P0  rename execution → host placement
P0  host/runtime cardinality
P1  host entrypoint + Mode A adapter
P2  observation ingestion + config snapshot
P3  Mode B host-to-host job protocol
P4  remote workspace/artifact
```

### 13.10 Verdict

```text
Direction: correct
Current plan: foundation, not best yet
Naming law: resolved
Blocking: host/runtime cardinality, host entrypoint, observation contract,
          config snapshot, host read auth
Mode A: feasible after P1
Mode B: feasible after P3/P4
```

## 15. Pipeline workflows

### 15.1 Host registration / model report

```text
Host runtime starts
  → discover models (cursor-agent models / agy models)
  → PUT /api/v1/host-runtimes/:hostId
  → POST /heartbeat {health, models, defaultModel}
  → ESO stores registry
  → UI Hosts shows runtime/models/default
```

Failure:

```text
models empty       → host shown pending; no placement use
ESO offline        → host runs local; registry sync later
```

### 15.2 Config publish / host read

```text
canonical files (agents/, flows/)
  → ESO indexes/publishes flow + worker config
  → operator sets host binding + worker placement
  → ESO produces config snapshot + hash (future)
  → host pulls snapshot
  → host verifies hash
  → host caches for offline
```

Failure:

```text
ESO offline   → host uses last cached snapshot
hash mismatch → host rejects snapshot; operator resolves
```

### 15.3 Mode A — same host, different model

```text
User prompt in Cursor/AGY
  → host entrypoint activates SLP
  → config reader loads snapshot
  → flow engine selects worker
  → model resolver maps modelTier → model
  → adapter executes on same host
  → gate evidence
  → host evaluates next edge
  → observation writer sends activity
  → ESO UI displays observation
```

Failure:

```text
model missing       → block host execution
evidence missing    → gate fail
adapter unavailable → host reports blocked observation
```

### 15.4 Mode B — different host, different model

```text
User prompt in host A
  → config: worker allowedHosts includes host B
  → host A builds job envelope
      workspace ref/commit
      worker prompt/policy
      model tier
      evidence requirements
  → host B executes
  → host B returns outcome + evidence + artifacts
  → host A validates evidence
  → host A evaluates flow
  → observation writer sends activity with host B ids
  → ESO UI displays
```

Failure:

```text
host B offline        → fallback host / block
auth failed           → block; no raw SSH fallback unless approved
workspace mismatch    → reject job
evidence invalid      → gate fail
```

### 15.5 Observation pipeline

```text
host event
  → observation envelope
      observation_id (idempotency)
      trace_id
      host_id/runtime_id
      worker_id
      event/outcome/evidence
      at
  → POST /consumers/:id/observations (future)
  → ESO append-only store
  → UI observatory read
```

Failure:

```text
ESO offline   → host buffers; retry with same observation_id
duplicate     → idempotent ignore
invalid       → reject; host logs
```

### 15.6 Human workflow

```text
1. Operator registers hosts
2. Operator configures host bindings
3. Operator configures worker placement
4. Operator edits/publishes flow
5. Operator prompts inside host
6. Host executes SLP
7. Host sends observation
8. Operator reads ESO observatory
9. Operator adjusts config
```

No step in this workflow is an ESO prompt or ESO execution.

### 15.7 Pipeline ownership

| Step | Owner | ESO surface |
|---|---|---|
| prompt | operator/host | none |
| config read | host | read-only snapshot |
| flow evaluation | host | none |
| model selection | host | registry catalog read |
| execution | host | none |
| evidence | host | observation ingest |
| observation storage | ESO | append-only |
| display | ESO UI | read-only |
| config edit | operator/ESO UI | config APIs |

### 15.8 Hard failure matrix

| Failure | Mode A | Mode B |
|---|---|---|
| ESO offline | host continues from cache | host continues from cache |
| host A offline | n/a | no dispatch |
| host B offline | n/a | fallback/block |
| model missing | block | block |
| evidence missing | gate fail | gate fail |
| snapshot hash mismatch | reject config | reject config |
| observation ingest down | buffer | buffer |
