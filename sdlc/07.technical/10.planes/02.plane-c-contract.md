# Plane C — Contract baseline (HTTP API)

**Một chủ đề:** hợp đồng HTTP của control plane baseline. Không quyết định DDL (plane D), không hành vi nội bộ (plane B).

## 1. Chung

| | |
|---|---|
| Base URL | `http://127.0.0.1:8787` |
| Auth | `Basic` (UI) · `Bearer <ESO_API_TOKEN>` (máy) |
| Content | `application/json; charset=utf-8` |
| Envelope lỗi | `{ code, message, detail? }` — `code` ⊆ BRD `06` |
| Version | `/api/v1/` |
| CORS | allowlist `127.0.0.1:4200` · `localhost:4200`; GET,POST,PUT,DELETE,OPTIONS |

### 2.1 `POST /api/v1/consumers/{id}/hosts/sync`

**Mục đích:** operator chọn một/nhiều host; sinh/merge projection từ canonical `AGENTS.md` + `agents/` + `.harness/`; **không** đổi consumer version.

**Request**

```json
{
  "hosts": ["cursor", "antigravity", "claude"],
  "expected_version": 1
}
```

- `hosts[]` bắt buộc, 1..7, không trùng; operator chọn, không auto-detect.
- `expected_version` optional; nếu có và lệch ⇒ 409 `STALE_VERSION` (cùng luật `PUT`).
- `Idempotency-Key` optional; cùng key + cùng payload ⇒ cùng kết quả.

**Response 200**

```json
{
  "consumer": "repo-a",
  "version": 1,
  "synced": [
    { "host": "cursor", "status": "synced", "files": [".cursor/rules/eso.mdc"] },
    { "host": "claude", "status": "partial", "files": [], "reason": "merge skipped user file" }
  ],
  "manifest": { "schema": "eso.harness-manifest.v1", "updated_at": "..." }
}
```

- `status` ∈ `synced` · `partial` · `conflict`; consumer `version` **không đổi**.
- 200 dù một host `partial`; 409 khi có `PROJECTION_CONFLICT` toàn request.

**Conflict / merge**

| Mã | HTTP | Khi |
|---|---|---|
| `HOST_UNSUPPORTED` | 400 | host ngoài danh sách |
| `CANONICAL_MISSING` | 422 | chưa có `AGENTS.md`/`agents/`/`.harness/` |
| `PROJECTION_CONFLICT` | 409 | file ESO-owned bị sửa tay **và** không merge an toàn; detail `{host,path,reason}` |
| `SYNC_FAILED` | 500 | ghi projection lỗi |

**Merge marker**

- File ESO sinh có header `generated by eso — do not edit` (cùng marker `.harness/config.json`).
- `.harness/manifest.json` giữ `projections[host].files[] = {path, sha256, owned:true, synced_at}`.
- Sync: `sha256` khớp manifest ⇒ overwrite; khác ⇒ `PROJECTION_CONFLICT` (không ghi đè); file không có trong manifest ⇒ không chạm.
- Hybrid: file ESO-owned generate; file người dùng merge nếu adapter khai merge rule; không overwrite mù.

### 2.2 `POST /api/v1/consumers/{id}/provision`

**Mục đích:** provision schema + material + setup info cho consumer đã có; idempotent.

```json
{
  "root": "/Users/.../repo-A",
  "material": { "agents": true, "harness": true, "manifest": true },
  "expected_version": 1
}
```

**Response 200**

```json
{
  "consumer": "repo-a",
  "status": "provisioned",
  "schema": "c_repo-a",
  "material": {
    "agents": true,
    "harness": ".harness/config.json",
    "manifest": ".harness/manifest.json"
  },
  "setup": { "ready": true, "updated_at": "..." }
}
```

- Schema `c_<id>`; **schema-expanded** (D-125), không shared schema, không database riêng.
- Material bundle: `AGENTS.md`, `agents/`, `.harness/config.json`, `.harness/manifest.json`.
- Idempotent: chạy lại không duplicate; lệch id/schema ⇒ `SCHEMA_MISMATCH`.
- Không đổi consumer version.

**Error**

| Mã | HTTP | Khi |
|---|---|---|
| `CONSUMER_NOT_FOUND` | 404 | consumer không tồn tại/không ready |
| `ROOT_NOT_FOUND` | 422 | root không tồn tại |
| `SCHEMA_MISMATCH` | 409 | `c_<id>` không khớp consumer |
| `MATERIAL_FAILED` | 500 | ghi material lỗi |
| `PROVISION_FAILED` | 500 | transaction/tổng hợp lỗi |

### 2.3 `GET /api/v1/consumers/{id}/setup`

Read-back setup info; 404 nếu consumer không tồn tại; `SETUP_INFO_MISSING` nếu chưa provision.


## 3. Ngữ nghĩa

- Consumer **chỉ** từ path, không từ token/body.
- `PUT` = optimistic lock: thiếu/sai `expected_version` ⇒ 409.
- `purge` không hoàn tác; `confirm_id` phải khớp.
- 404 thống nhất cho không tồn tại/retired/deleted/purged.

## 4. Quyết định / không quyết định

| Quyết định | Không quyết định |
|---|---|
| route · method · status · mã lỗi | DDL/bảng (→ plane D) |
| auth scheme · CORS | UI state machine (→ 08.ui-design) |

## 5. Revision rule

Thêm/đổi route hoặc mã lỗi ⇒ đăng ký mã ở BRD/06 trước (`D-104`), bump version; packet liên quan xem lại.
