# `27` — Host observation payload: rich schema cho prompt.submitted

> Sinh bởi `scripts/setup-consumer-hosts.mjs` (hook `.harness/hooks/eso-observe.mjs`).
> Mục tiêu: hook AGY/Cursor/DSH gửi **cùng schema rich** như worker bridge, để cột
> Model/Tier/Task/Flow trên Observatory có dữ liệu thay vì `not captured`.

## 1. Vì sao có tài liệu này

Đo 2026-11-24: cùng host AGY, cùng `worker-lead`, hai payload khác nhau:

| Trace | Evidence keys | Kết quả UI |
|---|---|---|
| `ed466a98` | `boundaryIndex · conversationId · generationId · host · promptText · runtimeKey · source · userQuery` | Model/In/Out/Calls trống |
| `95538925` | `adapter · hostStep · model · tier · userQuery` | Model hiện |

Nguyên nhân: hook cha chỉ gửi metadata prompt (minimal), trong khi worker bridge gửi rich.
ESO **không strip** field — nó lưu nguyên văn (chứng minh: bản rich 16:48 vẫn đủ field sau khi nâng cấp).

## 3. Luật

1. **Không bịa**: `model`/`tier` không có ⇒ `null`, `modelSource='not-reported'`.
2. Token chỉ lấy từ `usage` của host; không ước lượng ở hook.
3. Hook không được làm chậm/block host: lỗi mạng ⇒ buffer `.harness/hooks/eso-observe-outbox.jsonl`, exit 0.
4. Mỗi prompt = một trace (`conversationId:hash`) — không gộp cả conversation vào một request.

## 4. Turn completion (Stop hook)

Prompt hook chỉ có metadata lúc bắt đầu. Để có **In/Out/Calls/Tools**, Stop hook
(`eso-transcript-ingest.mjs`) đọc transcript và post **một** `worker.completed` cho parent trace:

| Field | Lấy từ |
|---|---|
| `tokenSummary{input,output}` | `input_tokens` / `output_tokens` của các `PLANNER_RESPONSE` |
| `tools[]` | `tool_calls` trong turn (sau `USER_INPUT` gần nhất) |
| `model` | `model` của `PLANNER_RESPONSE` |
| `durationMs` | từ `USER_INPUT.created_at` tới lúc Stop |
| idempotency | `host-turn-complete:<traceId>` — replay không nhân đôi |

Đo thật: trace `probe-turn-…` → `in 14798 · out 14 · calls 1` (tools 0 vì transcript mẫu không có `tool_calls`).

## 7. Contract S2/S3/S5 — `evidence.packet`, `evidence.verified`, `decision.recorded`

Đo theo `eso/control-plane/src/modules/observations/event-contract.ts` (`SCHEMA_VERSION = 1`), `eso/control-plane/src/modules/observations/observation.service.ts`, `eso/control-plane/src/modules/judgment/evidence-predicate.service.ts`, `host-runtime/src/answer-collector.ts`, và `host-runtime/src/entrypoint.ts` (2026-11-26):

### 7.1 `evidence.packet` (host → ESO)

- Bắt buộc có ít nhất một trong `evidence.items[]` (mảng không rỗng) hoặc `evidence.hash` (non-empty string); lỗi schema trả `422 OBSERVATION_INVALID` (hoặc `422 SCHEMA_UNSUPPORTED` nếu `schemaVersion > 1`).
- Mỗi phần tử `evidence.items[]` (`EvidencePacketItem`):
  - `id`: string bắt buộc (e.g. relative file path, `<doc>#<section>`, doc id)
  - `kind`: string bắt buộc (e.g. `'file'`, `'knowledge'`, `'KB_TEMPLATE_PRESENT'`, `'KB_DOC_HAS_SECTION'`, `'KB_INDEX_COVERS'`, `'SNAPSHOT_MATCHES'`)
  - `hash?`: string optional (SHA-256 hex)
  - `requirementId?`: string optional (neo requirement mà bằng chứng trả lời)
- Trường cấp packet optional: `hash?`, `specVersion?` (string | number), `actor?: { kind: 'host' | 'operator' | 'agent', id: string, role?: string }`, `schemaVersion?: 1`.

### 7.2 `evidence.verified` (server-appended tại ingest — S2/S5)

- Trigger Option A (`observation.service.ts:145-173`, `evidence-predicate.service.ts:101-190`): chạy sau khi `evidence.packet` đã được lưu (`created === true`), chỉ khi có ít nhất 1 item mang `requirementId` khác null hoặc `kind` thuộc `{'knowledge', 'file', 'KB_TEMPLATE_PRESENT', 'KB_DOC_HAS_SECTION', 'KB_INDEX_COVERS', 'SNAPSHOT_MATCHES'}`.
- **Bất biến:** ingest **không bao giờ** từ chối `evidence.packet` vì verify thất bại; kết quả verify chỉ được append thành một observation nội bộ mới:
  - `observationId`: `<packetObservationId>:verified` · `idempotencyKey`: `<idempotencyKey>:verified`
  - `hostId`: `'eso'` · `runtimeKey`: `'eso:predicate-verifier'` · `workerId`: `null`
  - `event`: `'evidence.verified'` · `outcome`: `'verified' | 'unverified'`
  - `evidence`: `{ actor: { kind: 'eso', id: 'predicate-verifier' }, packetObservationId, allVerified, snapshotId, verifiedAt, sources: VerifiedEvidenceSource[] }`
  - Mỗi `VerifiedEvidenceSource`: `{ requirementId, id, kind, where, hash, verified, reason?, verifiedAt }`
- S5 (`eso/control-plane/src/modules/receipt/receipt.service.ts:128-184`): `ReceiptService` trích `sources[]` từ `evidence.verified` để niêm phong vào `platform.evidence_receipt.payload` (`specVersion: 2`); `VerdictService` thêm gap `EVIDENCE_UNVERIFIED` nếu có item `verified === false`.

### 7.3 Host-runtime S3 contract emitters (`host-runtime/src/entrypoint.ts` + `answer-collector.ts`)

1. **`collectLocalAnswers` & `extractCitedFilePaths`** (`host-runtime/src/answer-collector.ts`): kiểm tra file cục bộ qua `node:fs` + SHA-256 dưới `cwd` (từ pre-step `judgment.requirements` + `AGENTS.md`, `report.files`, và đường dẫn trích từ `stdout`); file không tồn tại ra `exists: 'absent'` và không vào `packetItems`.
2. **`evidence.packet`** (`entrypoint.ts:729-758`): gửi khi `packetItems.length > 0`, kèm `hash: computePacketHash(packetItems)`, `actor: { kind: 'host', id: worker.id, role? }`, `schemaVersion: 1`, `idempotencyKey: <traceId>:<workerId>:evidence-packet:<hostStep>`.
3. **`action.recorded`** (`entrypoint.ts:761-789`): gửi khi `executionMode !== 'B' || Boolean(options.judgment) || packetItems.length > 0`, mang `{ tool: adapterName, outcome, files: verifiedRelativePaths, actor, schemaVersion: 1 }`, `idempotencyKey: <traceId>:<workerId>:action:<hostStep>`.
4. **`decision.recorded`** (`entrypoint.ts:791-835`): gửi cùng điều kiện trên, mang `{ winner: worker.id, verdict: 'allow'|'deny'|'partial', basis, latencyMs, actor, judgment?, gaps?, schemaVersion: 1 }`, `idempotencyKey: <traceId>:<workerId>:decision:<hostStep>`.
