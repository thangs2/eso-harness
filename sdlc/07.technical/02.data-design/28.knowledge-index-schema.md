# 28 — Knowledge index schema (Postgres) — greenfield

**Trạng thái:** **APPLIED GREENFIELD 2026-11-12** — không migrate; schema được tạo mới. Đọc cùng
[`22.knowledge-manifest-and-index`](../01.architecture/22.knowledge-manifest-and-index.md).

**Phạm vi:** index tài liệu/manifest cho **một consumer schema** (`c_<id>`). Không thay
`platform.consumer`, `platform.harness_stack_version`, hay graph code hiện tại.

## 1. Đo thực tế 2026-11-12

Sau khi chuyển image Postgres sang `pgvector/pgvector:pg16`:

```text
Postgres        16.15 (Debian)
Database        eso
Extensions      pgcrypto 1.3 · vector 0.8.7 · pg_trgm 1.6 · unaccent 1.1
FTS             built-in
```

Tables:

```text
platform.consumer
platform.consumer_event
platform.harness_stack_version
```

Consumer schema:

```text
c_testeso = 22 tables
  14 knowledge_type rows
  9 knowledge_doc rows
  7 knowledge_worker rows
  1 knowledge_flow row
```

Greenfield bootstrap:

```text
eso/control-plane/sql/knowledge.greenfield.sql   destructive reset (manual only)
eso/control-plane/sql/knowledge.bootstrap.sql   non-destructive CREATE IF NOT EXISTS
```

`ensureKnowledgeSchema()` chạy bootstrap này sau `CREATE SCHEMA` cho consumer mới.
`knowledge.greenfield.sql` không dùng cho consumer đang live vì có `DROP SCHEMA`.

## 2. Nguyên tắc thiết kế

```text
1 schema / consumer
file = content SoT
DB   = derived index
doc_id = identity
path   = locator
edge   = relation + provenance
FTS    = text retrieval
vector = optional, derived (pgvector image; embedding pipeline chưa chạy)
```

Không join cross-consumer. Không copy content vào DB ngoài text extraction phục vụ search.

## 3. Bảng trong `c_<id>`

### 3.1 `knowledge_type`

```sql
CREATE TABLE knowledge_type (
  type              text PRIMARY KEY,
  label             text NOT NULL,
  required_sections jsonb NOT NULL DEFAULT '[]'::jsonb,
  header_profile    jsonb NOT NULL DEFAULT '{}'::jsonb,
  default_owner     text,
  representation    text NOT NULL CHECK (representation IN ('human','agent','machine')),
  default_liveness  text NOT NULL DEFAULT 'living' CHECK (default_liveness IN ('frozen','living')),
  default_kt_state  text NOT NULL DEFAULT 'raw' CHECK (default_kt_state IN ('raw','proposed','approved','retired')),
  created_at        timestamptz NOT NULL DEFAULT now()
);
```

`type` là catalogue đóng. `header_profile` chứa key bắt buộc cho HUMAN/AI; **không** copy toàn bộ
facet vào từng file.

### 3.2 `knowledge_doc`

```sql
CREATE TABLE knowledge_doc (
  doc_id            text PRIMARY KEY,
  path              text NOT NULL,
  type              text NOT NULL REFERENCES knowledge_type(type),
  status            text NOT NULL CHECK (status IN ('DRAFT','OPEN','READY','READY-SPLIT','BLOCKED')),
  owner             text,
  representation    text NOT NULL CHECK (representation IN ('human','agent','machine')),
  origin            text NOT NULL DEFAULT 'human' CHECK (origin IN ('human','agent','machine')),
  custodian         text NOT NULL DEFAULT 'repo' CHECK (custodian IN ('repo','provider','plugin')),
  liveness          text NOT NULL DEFAULT 'living' CHECK (liveness IN ('frozen','living')),
  kt_state          text NOT NULL DEFAULT 'raw' CHECK (kt_state IN ('raw','proposed','approved','retired')),
  source_doc_id     text REFERENCES knowledge_doc(doc_id) ON DELETE SET NULL,
  human_sot_doc_id  text REFERENCES knowledge_doc(doc_id) ON DELETE SET NULL,
  source_pointer    text,
  human_sot_pointer text,
  title             text,
  content_hash      text NOT NULL,
  header_json       jsonb NOT NULL DEFAULT '{}'::jsonb,
  indexed_at        timestamptz NOT NULL DEFAULT now(),
  CONSTRAINT knowledge_doc_path_not_empty CHECK (length(path) > 0),
  CONSTRAINT knowledge_doc_hash_not_empty CHECK (length(content_hash) > 0),
  CONSTRAINT knowledge_doc_no_self_source CHECK (source_doc_id IS DISTINCT FROM doc_id),
  CONSTRAINT knowledge_doc_no_self_human CHECK (human_sot_doc_id IS DISTINCT FROM doc_id)
);
```

`path` ở đây là **current locator**; lịch sử ở `knowledge_doc_path`.

### 3.3 `knowledge_doc_path`

```sql
CREATE TABLE knowledge_doc_path (
  doc_id     text NOT NULL REFERENCES knowledge_doc(doc_id) ON DELETE CASCADE,
  path       text NOT NULL,
  valid_from timestamptz NOT NULL DEFAULT now(),
  valid_to   timestamptz,
  PRIMARY KEY (doc_id, path, valid_from)
);

CREATE UNIQUE INDEX knowledge_doc_path_one_current
  ON knowledge_doc_path (path)
  WHERE valid_to IS NULL;
```

Không unique `path` toàn bảng: file có thể move; current path mới là unique.

### 3.4 `knowledge_edge`

```sql
CREATE TABLE knowledge_edge (
  edge_id     text PRIMARY KEY,
  from_doc_id text NOT NULL REFERENCES knowledge_doc(doc_id) ON DELETE CASCADE,
  to_doc_id   text NOT NULL REFERENCES knowledge_doc(doc_id) ON DELETE CASCADE,
  kind        text NOT NULL CHECK (kind IN (
                'references','derived_from','source_of_truth','human_sot',
                'supersedes','owns_kinds','blocks','mentions_ticket'
              )),
  conflict    boolean NOT NULL DEFAULT false,
  created_at  timestamptz NOT NULL DEFAULT now(),
  UNIQUE (from_doc_id, to_doc_id, kind),
  CONSTRAINT knowledge_edge_no_self CHECK (from_doc_id <> to_doc_id)
);

CREATE INDEX knowledge_edge_from ON knowledge_edge (from_doc_id, kind);
CREATE INDEX knowledge_edge_to   ON knowledge_edge (to_doc_id, kind);
```

### 3.5 `knowledge_edge_claim`

Append-only provenance, cùng pattern `source_claim`:

```sql
CREATE TABLE knowledge_edge_claim (
  edge_id    text NOT NULL REFERENCES knowledge_edge(edge_id) ON DELETE CASCADE,
  seq        integer NOT NULL CHECK (seq >= 1),
  provenance text NOT NULL CHECK (provenance IN ('declared','derived')),
  source     text NOT NULL CHECK (source IN ('header','markdown-link','provider','path')),
  claim      text NOT NULL,
  at         timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (edge_id, seq)
);
```

### 3.6 `knowledge_link`

Raw link attempts, kể cả unresolved:

```sql
CREATE TABLE knowledge_link (
  link_id          bigserial PRIMARY KEY,
  doc_id           text NOT NULL REFERENCES knowledge_doc(doc_id) ON DELETE CASCADE,
  raw_target       text NOT NULL,
  resolved_doc_id  text REFERENCES knowledge_doc(doc_id) ON DELETE SET NULL,
  resolved_anchor  text,
  status           text NOT NULL CHECK (status IN ('resolved','unresolved','external','anchor-missing')),
  provenance       text NOT NULL DEFAULT 'declared',
  created_at       timestamptz NOT NULL DEFAULT now()
);

CREATE INDEX knowledge_link_unresolved
  ON knowledge_link (doc_id)
  WHERE status <> 'resolved';
```

### 3.7 `knowledge_external_ref`

```sql
CREATE TABLE knowledge_external_ref (
  doc_id      text NOT NULL REFERENCES knowledge_doc(doc_id) ON DELETE CASCADE,
  provider    text NOT NULL,
  external_id text NOT NULL,
  kind        text NOT NULL CHECK (kind IN ('ticket','story','task','bug','design','document')),
  url         text,
  direction   text NOT NULL DEFAULT 'out' CHECK (direction IN ('in','out')),
  PRIMARY KEY (doc_id, provider, external_id, kind)
);

CREATE INDEX knowledge_external_ref_lookup
  ON knowledge_external_ref (provider, external_id);
```

Provider không phải enum đóng ở DB; registry ở app. DB chỉ giữ link.

### 3.8 `knowledge_doc_search`

```sql
CREATE TABLE knowledge_doc_search (
  doc_id  text PRIMARY KEY REFERENCES knowledge_doc(doc_id) ON DELETE CASCADE,
  tsv     tsvector NOT NULL,
  excerpt text NOT NULL DEFAULT ''
);

CREATE INDEX knowledge_doc_search_tsv ON knowledge_doc_search USING GIN (tsv);
CREATE INDEX knowledge_doc_search_trgm ON knowledge_doc_search USING GIN (excerpt gin_trgm_ops);
```

Dùng `simple` config cho Vietnamese/mixed; `unaccent` optional.

### 3.9 `knowledge_doc_chunk` — vector (enabled)

Đã enable vì image có `vector` extension. Embedding vẫn là **optional derived data**:

```sql
CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE knowledge_doc_chunk (
  chunk_id  text PRIMARY KEY,
  doc_id    text NOT NULL REFERENCES knowledge_doc(doc_id) ON DELETE CASCADE,
  ordinal   integer NOT NULL,
  anchor       text,
  text         text NOT NULL,
  content_hash text,
  embedding    vector(1024),
  model     text,
  UNIQUE (doc_id, ordinal)
);

CREATE INDEX knowledge_doc_chunk_doc ON knowledge_doc_chunk (doc_id);
CREATE INDEX knowledge_doc_chunk_vec
  ON knowledge_doc_chunk USING hnsw (embedding vector_cosine_ops);
```

Bảng và HNSW index tồn tại; `testeso` hiện có 22/22 chunks embedded bằng `BAAI/bge-m3` (1024 dims). Core search không phụ thuộc bảng này.

## 5. Query patterns

### 5.1 Direct / reverse

```sql
-- outgoing
SELECT e.kind, d.doc_id, d.path
FROM knowledge_edge e JOIN knowledge_doc d ON d.doc_id = e.to_doc_id
WHERE e.from_doc_id = $1;

-- reverse
SELECT e.kind, d.doc_id
FROM knowledge_edge e JOIN knowledge_doc d ON d.doc_id = e.from_doc_id
WHERE e.to_doc_id = $1;
```

### 5.2 Transitive 1–3

```sql
WITH RECURSIVE walk(doc_id, depth, path) AS (
  SELECT $1::text, 0, ARRAY[$1::text]
  UNION ALL
  SELECT e.to_doc_id, w.depth + 1, w.path || e.to_doc_id
  FROM walk w
  JOIN knowledge_edge e ON e.from_doc_id = w.doc_id
  WHERE w.depth < 3
    AND NOT e.to_doc_id = ANY(w.path)
)
SELECT DISTINCT doc_id, depth FROM walk;
```

Depth cap 3; không nhận tham số không trần từ client.

### 5.3 Text

```sql
SELECT d.doc_id, d.path, ts_rank(s.tsv, q) AS rank
FROM knowledge_doc_search s
JOIN knowledge_doc d USING (doc_id)
CROSS JOIN websearch_to_tsquery('simple', $1) q
WHERE s.tsv @@ q
ORDER BY rank DESC
LIMIT 50;
```

### 5.4 Ticket

```sql
SELECT doc_id, provider, external_id, url
FROM knowledge_external_ref
WHERE provider = $1 AND external_id = $2;
```

### 5.5 Flow / event

```sql
-- default flow + versions
SELECT flow_id, version, status, is_default
FROM knowledge_flow
WHERE is_default = true
ORDER BY version DESC;

-- worker events for a trace
SELECT event_id, worker_id, event, decision, trace_id, span_id
FROM knowledge_worker_event
WHERE trace_id = $1
ORDER BY created_at, event_id;
```



```sql
SELECT doc_id, chunk_id, embedding <=> $1 AS distance
FROM knowledge_doc_chunk
ORDER BY embedding <=> $1
LIMIT 30;
```

Không expand graph tự động từ vector result; application quyết định.

## 7. Build index flow

```text
1. scan files outside DB
2. parse header + validate profile
3. resolve doc_id/path map
4. begin transaction
5. upsert knowledge_doc + knowledge_doc_path
6. delete/reinsert edges for this build
7. insert links + claims + external refs
8. update knowledge_doc_search
9. insert knowledge_index_run
10. commit
11. optional embeddings async
```

Nếu fail giữa chừng: rollback transaction; index cũ vẫn dùng được. `knowledge_index_run` ghi error.

## 8. Volume / cost

Ước lượng ban đầu:

```text
docs        10^3–10^4
edges       10^4–10^5
chunks      10^5
vector      1024 dim × 4 bytes ≈ 6 KB/chunk
            10^5 chunks ≈ 600 MB + HNSW
```

Quyết định:

- chưa partition; schema-per-consumer đã cô lập;
- vector chỉ bật khi có use case semantic và pgvector;
- FTS + trigram đủ cho search text;
- closure table chỉ thêm nếu traversal >3 hop thực sự cần và có benchmark.

## 9. Risk / lỗi cần tránh

| Rủi ro | Cách chặn |
|---|---|
| path làm identity | `doc_id` PK; path history |
| sửa `ddl.ts` mà không migrate | migration runner bắt buộc |
| vector thành dependency | optional extension/migration |
| edge mồ côi | FK + delete cascade + orphan check |
| unresolved link bị bỏ qua | `knowledge_link.status` |
| copy ticket content | external_ref only |
| cross-consumer leak | schema per consumer, no cross-schema query |
| index dùng content cũ | content_hash + index_run |
