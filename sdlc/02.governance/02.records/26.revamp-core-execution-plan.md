# `26` — Planning revamp ESO core execution (để review)

> **Đọc trước:** [`25.expectation-gap-audit`](25.expectation-gap-audit.md) §0.1 — kỳ vọng = **legacy ++++**
> (B0 sàn + Δ). Kế hoạch này đưa ESO từ **B0 ≈1.5/10** lên **B0 10/10**, rồi mới làm Δ.
> Operator **APPROVED 2026-11-24**: D1–D7 theo đề xuất; thi công chia subagent theo phase.
> Chốt: **D1=(c)** host khai + ESO adjudicate · **D2** hash-chain + HMAC host key · **D3** `not_captured` + `partial` · **D4** snapshot + version · **D5** bảng riêng · **D6** hash + redacted · **D7=A**.

## 1. Vấn đề & mục tiêu

| | |
|---|---|
| **Hiện trạng** | Detail page chỉ *kể lại event*; gọi **1 API** (`getRequestDetail`); không verdict · actor · sufficiency/gaps · receipt · what-changed ⇒ **V3 không đạt** |
| **Mục tiêu** | Detail page trở thành **bề mặt chứng minh**: người thứ ba trả lời đúng "vì sao turn này được cho qua" **chỉ từ bản ghi**, không mở log |
| **Thước đo** | B0 10/10 · V3 ≥8/10 turn · 6 câu hỏi §2 trả lời được · Δ giữ nguyên hoặc tăng |
| **Không làm** | ESO **không** chạy/execute/chat/spawn (invariant `core.eso-sidecar`) — "core execution" ở đây là **đường ống chứng minh** của ESO, không phải runtime agent |

### 1.1 "Revamp core execution" nghĩa là gì (cần chốt)

| Cách hiểu | Nội dung | Đánh giá |
|---|---|---|
| **A. Execution evidence** *(đề xuất)* | Revamp pipeline `Route → Collect → Score/Gate → Report` để **chứng minh** execution của host: decision, verdict, sufficiency, receipt, what-changed | đúng invariant, đóng V3 |
| B. ESO tự execute | ESO chạy worker/model | **vi phạm** `core.eso-sidecar` — cần quyết định mới thay đổi invariant |
| C. Chỉ làm UI đẹp hơn | thêm block hiển thị | không đóng được B0-3/B0-5 (không có dữ liệu) |

> Kế hoạch chọn **A**. Nếu operator muốn **B**, phải mở decision riêng (đảo invariant) trước.

## 4. Kiến trúc đích (A)

```text
Host (Cursor/AGY/DSH/...)                ESO control-plane                    Surfaces
─────────────────────────                ─────────────────                    ────────
turn ─┬─ prompt.submitted ───────────────▶ ingest (durable)
      ├─ decision.recorded  (mới) ───────▶ decision_log  ──┐
      ├─ action.recorded    (mới) ───────▶ action_log     ├─▶ turn_verdict ─┐
      ├─ evidence.packet    (mới) ───────▶ evidence_ledger│   (append-only)  ├─▶ detail page
      └─ turn.completed ─────────────────▶ observations   │                  │   (6 block)
                                                           │                  ├─▶ report artifact
                                        sufficiency/judgment ┘                 └─▶ V3 replay test
                                        receipt = hash(chain + snapshot)
```

**Nguyên tắc:** host sở hữu execution; ESO **không tin lời khai** — mọi claim phải kèm evidence ref, ESO chấm và ký kết quả.

## 6. Thay đổi dữ liệu (sơ bộ — chưa chốt)

| Bảng | Cột chính | Ghi chú |
|---|---|---|
| `platform.decision_event` | `trace_id · at · kind · winner · jev_mode · verdict · latency_ms · refs jsonb` | append-only |
| `platform.action_event` | `trace_id · at · tool · files jsonb · read_before_edit bool · outcome` | từ host action |
| `platform.turn_verdict` | `trace_id · level · basis · actor · role · gaps jsonb · score · rule_refs · receipt_id` | 1 dòng / turn |
| `platform.evidence_receipt` | `receipt_id · trace_id · prev_hash · hash · hmac · spec_version` | chain |

**v1 (P1) rút gọn có chủ đích:** `decision.recorded` · `action.recorded` · `evidence.packet` là **event có schema validate**,
lưu trong `knowledge_observation` (log thô) + cột `actor`/`schema_version` trong `evidence` JSONB; **chưa** tạo bảng riêng.
Chỉ tách bảng khi truy vấn verdict cần. `platform.turn_verdict` + `platform.evidence_receipt` vẫn tạo ở P2/P4.

Giữ `knowledge_observation` làm log thô; không nhét verdict vào đó (một nội dung một nhà).

## 10. Việc **không** làm trong revamp này

- Không để ESO chạy/route/execute agent (invariant).
- Không làm microservices (B2 deferred, x79).
- Không thêm block UI khi chưa có nguồn dữ liệu thật.
- Không "làm đẹp" legacy parity bằng dữ liệu giả.
