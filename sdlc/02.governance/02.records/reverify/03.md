**WRONG-1 (rendered text ≠ doc).** FRD 38 §7.3 A12 and UI 07 §1 E14 both promise a preview header
`n candidates · n skipped`. The template interpolates a stray source expression:

```html
<!-- stack-tab.component.html:119 -->
<p>{{ preview.candidates.length }} vm().rule(s) · {{ preview.skipped.length }} skipped</p>
```

so the page literally renders `3 vm().rule(s) · 1 skipped`. Contradicted sentence: *"Preview | `n candidates · n skipped`; đóng bằng Cancel"*
(FRD 38, A12) and *"Preview header `n candidates · n skipped` + `Cancel`"* (UI 07, E14). This is a **product defect**, not
a doc-only error — the doc describes intent, the code prints its own source.

**WRONG-2 (law incomplete).** FRD 38 A3 says reopen is legal when *"published, chưa retired"*. Code
(`settings-stack.base.ts:108-110`) is stricter: `status==='published' && !hostProfiles().some(p => p.stackVersion===active)`.
A version still pinned by any host binding is **not** reopenable. The doc omits that condition, so the stated law
permits an action the UI hides. Same omission in A5: `canDeleteStackVersion()` also requires `stackVersions().length > 1`
and no binding pin (`:82-86`).

**WRONG-3 (error catalog).** FRD 38 §7.5 lists `STACK_DENIED` / `STACK_UPSTREAM_FAILED` / `STACK_INVALID` as what is
shown. No such identifier exists in `eso/ui/**` (`grep -rn 'STACK_DENIED' eso/ui` → 0 hits). Stack persistence goes
through the settings shell, which sets `PROFILE_DENIED` / `PROFILE_STALE_VERSION` / `PROFILE_UPSTREAM_FAILED`
(`settings-tail.base.ts:281-285`), and rule-import failures set a bare message (`settings-stack.base.ts:286,324`).
The quote *"Hiện **mã + message**"* is therefore true only for the shell codes, not the three listed.
