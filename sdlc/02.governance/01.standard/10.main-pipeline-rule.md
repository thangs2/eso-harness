# `10` — SDLC Master Pipeline: Normative Rule

**Normative.** Source diagram: [`04.diagrams/01.main-pipeline`](../04.diagrams/01.main-pipeline.md).
This is the master pipeline `S1…S17` + `G1…G16` with 3 mandatory quantitative quality checkpoints (**CHK1 Cross-checks**, **CHK3 Pre-flight DoR**, **CHK2 Go / No-Go**). The Intent Pipeline is the **upstream zoom-in of `S1…S7`**.

## 1. Sequence Invariants & Unidirectional Authority

1. `S1 → S2 → … → S17` MUST proceed in strict sequential order; skipping stages or premature phase transition is STRICTLY FORBIDDEN.
2. Each gate `G1…G16` MUST possess documentary evidence or quantitative measurements before moving to the next stage.
3. `S1…S2` MUST incorporate the Intent Pipeline `I1…I3` (pain → vision/mission → goals & objectives with measurable metrics).
4. `S3…S7` MUST align with Intent Pipeline `I4…I7`; conflicting or parallel dual sources of truth MUST NOT exist.
5. **Technical Design (`S8…S10`)** MUST complete before work packages are scheduled:
   - `S8` API contracts MUST comply with the zero-turn-path rule (`D-46`) and standard error code catalogs.
   - `S9` Data Design MUST prove zero-drift between Entity models and actual Database Schemas.
   - `S10` Architecture MUST declare C4 L1–L3 diagrams and NFR specifications with measurable thresholds.
6. `S11` WBS MUST trace directly back to `S7 AC`; tickets without AC MUST NOT be created.
7. `S12` BIP/FIP packets MUST lock the `allowed_files` boundary and explicitly designate invariant enforcement.
8. `S13` Scenario Matrix MUST achieve 1:1 coverage with AC (covering happy, edge, failure, and RBAC/tenant paths).
9. **Mandatory Inspection Checkpoints:**
   - **CHK1 (Requirements)**: Cross-checks `X1, X2, X4–X7, X16–X20` green before handing off to TECH design (excludes `X3` as SCN is not yet authored).
   - **CHK3 (DoR per slice)**: Pre-flight Readiness Checklist completes all **8/8 pre-code rows (Stage 0–7)** plus `X3` (1:1 AC ↔ SCN) before implementation starts.
   - **CHK2 (Increment Planning)**: Go / No-Go Dashboard achieves full `Docs Ready` status (`REQ ∩ US/AC ∩ SCN ∩ IF ∩ DATA` + `BIP/FIP`) and passes technical cross-checks (`X8, X8a, X9, X10, X21, X22, X34–X36`) before funding `S14` execution.
10. `S14` Code MUST be authored within packet scope; editing outside `allowed_files` is FORBIDDEN; follows the designated Delivery Test Profile (Core Quartet: unit RED → impl GREEN → coverage ≥80% + declared profile dimensions: property, mutation, visual, a11y, contract, security, load, chaos).
11. `S15` QC MUST execute real SCN scenarios and capture `evidence.json` before DoD evaluation.
12. `S16` DoD Checklist (`D-116`) MUST achieve 0 CRITICAL unresolved findings.
13. `S17` MUST be signed off by **humans (PO & PM)**; agents or automated tools MUST NOT sign `Done` (BR-05).
14. CR loops only follow declared feedback edges in the diagram; bypassing gates via CR is FORBIDDEN.

## 3. Relationship with Intent Pipeline and Technical Design

| If | Then |
|---|---|
| Intent Pipeline modifies `I1…I8` | Main pipeline `S1…S7` and `S11…S12` MUST be reviewed; version bumped |
| Main pipeline modifies gates `G1…G16` | Intent rules `I-G1…I-G8` MUST be synchronously updated |
| Ticket cannot trace back to `S7 AC` | Ticket is invalid; editing ticket is forbidden, reopen Requirements stage |
| API Contract or Schema changes | Mandatory trigger of CR Pipeline ([`02.cr-pipeline`](../04.diagrams/02.cr-pipeline.md)), update BIP/FIP before code |
