# `15` — Đặc tả hành vi page (STD-PAGE-BEHAVIOR)

> **Vấn đề:** "page doc có inventory" vẫn chưa đủ. Người đọc cần biết: **điều kiện nào để có dữ liệu**, **if/else nào
> đổi giao diện**, **CTA nào bật/tắt vì sao**, **dữ liệu đến từ đâu**, **bấm thì gì xảy ra**, **lỗi nào hiện gì**.
> Chuẩn này bắt mỗi page phải có 10 khối dưới, mỗi dòng có `file:line`.

## 1. Mười khối bắt buộc

| Khối | Nội dung | Ví dụ câu trả lời |
|---|---|---|
| **B1 Entry** | route · guard · query param (và alias) · điều kiện tiên quyết | "`?consumer=` sai ⇒ dừng, không fallback" |
| **B2 Load sequence** | thứ tự gọi API, song song/tuần tự, nhánh lỗi từng bước | "consumers → (observations) → (flows ∥ consumer)" |
| **B3 Data graph** | field hiển thị ← computed ← endpoint ← bảng | "`Failures` ← `failureCount()` ← `observations` ← `GET .../observations`" |
| **B4 Branch table** | **mọi if/else** có ý nghĩa người dùng: predicate → kết quả | "`flows.length === 0` ⇒ text `No published flow`, **không** phải lỗi" |
| **B5 CTA table** | control → điều kiện bật → hành động → API → nhánh lỗi → state reset | "`Play` disabled khi `pulsePlaying`; chạy 450 ms/event" |
| **B6 State machine** | state × trigger → state kế | "`playing` --hết event--> `ready`" |
| **B7 Error paths** | status/code → UI hiện gì → retry? | "401/403 ⇒ `OBS_DENIED`; 500 ⇒ `OBS_UPSTREAM_FAILED`" |
| **B8 Derived** | công thức computed, thứ tự ưu tiên, edge case | "flow = default → published mới nhất → `flows[0]`" |
| **B9 Timing/live** | poll · SSE · interval · cleanup | "poll 5 s; SSE server 1.5 s; `ngOnDestroy` clear" |
| **B10 A11y/nav** | keyboard · focus · deep-link · back | "row không `tabindex` ⇒ **không** keyboard (gap)" |

## 2. Luật viết

1. **Mỗi dòng phải có `file:line`** — không có nghĩa là chưa đo.
2. **Branch table phải phủ hết `@if`/`@else`/ternary** trong template + `if/return` trong handler.
3. **CTA table phải nêu điều kiện disabled** thật (không chép lời hứa).
4. **Data graph phải chỉ ra bảng** (nếu có) — nếu là JSON/file thì ghi rõ.
5. **Không lặp rule FRD**: B4/B5 mô tả *hành vi UI thấy*, FRD mô tả *luật nghiệp vụ*.
6. **Gap phải ghi**: nếu code không có a11y/không có retry ⇒ ghi `GAP`, không né.

## 3. Đo độ sâu

| Chỉ số | Cách đo | Ngưỡng tối thiểu |
|---|---|---|
| `branch` | số dòng B4 | ≥ 8 với page phức tạp, ≥ 3 với page tĩnh |
| `cta` | số dòng B5 | = số control tương tác |
| `error` | số dòng B7 | ≥ 3 |
| `derived` | số dòng B8 | = số computed ảnh hưởng UI |

Page chưa đạt ngưỡng ⇒ ghi `DEPTH: n/m` trong page doc và giữ `DONE ✗`.
