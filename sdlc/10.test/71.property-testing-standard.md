# 71 — Property-testing standard

> **Hiệu lực:** mọi feature/function mới hoặc sửa đổi từ 2026-11-18.
>
> Property test không thay thế example test. Nó trả lời câu khác:
> *"điều gì luôn đúng với **mọi** input hợp lệ/không hợp lệ trong miền đã khai?"*

## 1. Khi nào bắt buộc

Bắt buộc có ít nhất một property test khi thay đổi chạm một trong các loại sau:

| Loại | Ví dụ |
|---|---|
| Transform / serialize | config canonicalization, JSON, hash, mapping |
| Protocol / envelope | sign/verify, request/response, retry |
| ID / dedupe / cache | observation id, idempotency key, ledger, buffer |
| Bounds / clamp / limit | max steps, tail size, retention |
| Security boundary | redaction, workspace allow-list, token scope |
| Resolver / policy | model/tier resolution, worker placement, fallback |
| State machine | flow transition, retry state, provisioning states |
| Parser / normalizer | DDL, date, URL, slug, JSONB |

Không cần property test cho:

```text
pure UI layout / CSS
one-line copy change
static config value
```

Nếu miễn: ghi `NO_PROPERTY: <lý do>` trong PR/evidence. Không được im lặng bỏ qua.

## 2. Property bắt buộc theo loại

| Nhóm | Property tối thiểu |
|---|---|
| **Roundtrip** | encode→decode trả lại đúng dữ liệu; sign→verify đúng |
| **Invariant** | output luôn nằm trong miền hợp lệ; bounds không vượt |
| **Idempotence** | cùng input → cùng output/id; retry không tạo bản ghi mới |
| **Uniqueness** | field khác nhau → id/kết quả khác nhau |
| **Tamper / negative** | sửa một field → bị từ chối, không fail-open |
| **Containment** | path/tenant/scope ngoài allow-list bị chặn |
| **Precedence** | explicit > tier > default, không bịa giá trị |
| **Metamorphic** | đổi thứ tự key / duplicate input không đổi kết quả |
| **Bounded output** | tail/response/retention không vượt giới hạn |

Một property tốt phải **sai được**: nếu xóa invariant trong code, test phải đỏ.

## 3. Quy trình 7 bước

```text
1. Invariant      viết một câu: "với mọi ..., phải ..."
2. Domain         khai generator: valid + invalid + boundary + adversarial
3. Oracle         assert độc lập, không lặp lại implementation
4. Seed           seed cố định; >=100 case cho pure, >=20 cho I/O
5. Failure        báo seed + iteration + case; replay bằng PROPERTY_SEED
6. Shrink         thu nhỏ counterexample nếu framework hỗ trợ
7. Evidence       ghi property, path, seed, kết quả
```

### 3.1 Generator

- Có `valid`, `invalid`, `boundary`, `adversarial`.
- Không generate dữ liệu chỉ để pass; phải chạm domain thật.
- Với path/workspace: tạo temp dir thật, không mock `existsSync`.
- Với crypto/protocol: generate field hợp lệ rồi mutate một field.

### 3.2 Oracle

- Assert **hệ quả**, không copy lại code.
- Ví dụ: `decode(encode(x)) === x`, không `decode` bằng chính hàm encode.
- Với security: assert **không leak** và **bị từ chối**, không chỉ assert status.

### 3.3 Failure evidence

Mọi failure phải có:

```text
property name
seed
iteration
generated case (JSON)
expected / actual
```

Replay:

```bash
PROPERTY_SEED=<seed> bun test <file> --test-name-pattern "<property>"
```

## 4. Framework

Repo dùng harness nội bộ, không thêm runtime dependency:

```text
host-runtime/test/property-harness.ts
```

Đặc điểm:

```text
seeded PRNG (mulberry32)
deterministic per seed + iteration
runs mặc định 100
failure in seed + iteration + case
PROPERTY_SEED để replay
```

Khi repo cho phép devDependency, có thể thay bằng `fast-check`; standard không đổi:
seed/replay/shrink/evidence vẫn bắt buộc.

## 5. Mode A/B — suite chuẩn

```text
host-runtime/test/modeab.property.test.ts
```

| Property | Bảo vệ |
|---|---|
| `clampMaxSteps` bounded | Mode A max-step không vượt trần |
| observation id/idempotency deterministic | retry không tạo observation mới |
| evidence redaction + bounded | prompt/secret không leak; tail bounded |
| explicit model wins | resolver không bịa model |
| `stableJson` key-order invariant | Mode B signature không phụ thuộc thứ tự key |
| signed job/result roundtrip + tamper | protocol không fail-open |
| workspace allow-list containment | B không chạy ngoài workspace |
| ledger replay same result | duplicate job không chạy lại |

Chạy:

```bash
cd host-runtime && bun test
```

## 6. Definition of Done

Một feature chỉ `Human In Review` khi:

```text
[ ] có property cho mọi invariant/transform/protocol/security thuộc §1
[ ] property chạy trong bun test, không cần service ngoài
[ ] seed/iteration/case có trong failure message
[ ] example test + regression test vẫn còn
[ ] property suite xanh
[ ] nếu miễn: NO_PROPERTY + lý do + reviewer đồng ý
```

Property test **không** thay:

```text
unit/example test
integration/E2E
visual audit
human/Done
```

## 7. Audit checklist

| # | Câu hỏi | Fail nếu |
|---|---|---|
| P1 | Property có phát biểu được bằng một câu? | test chỉ là example thứ hai |
| P2 | Domain có invalid/boundary? | chỉ generate happy path |
| P3 | Oracle độc lập? | assert lại implementation |
| P4 | Failure replay được? | không có seed/iteration |
| P5 | Có negative/security property? | chỉ assert success |
| P6 | Chạy deterministic? | random không seed |
| P7 | Property suite nằm trong CI? | test file không được chạy |

## 8. Ví dụ chuẩn

```ts
property(
  'signed job roundtrip preserves fields and rejects tampering',
  (r) => randomJob(r),
  async (job) => {
    const signed = await signJob(job, SECRET);
    expect(await verifyJobSignature(signed, SECRET)).toEqual(job);

    const tampered = { ...job, jobId: `${job.jobId}-x` };
    await expect(
      verifyJobSignature({ envelope: tampered, signature: signed.signature }, SECRET),
    ).rejects.toMatchObject({ code: 'ENVELOPE_SIGNATURE_INVALID' });
  },
);
```

## 9. Quan hệ với SLP

- **Build worker:** viết property trước hoặc cùng slice.
- **Verify worker:** chạy property suite; replay seed khi đỏ.
- **Audit worker:** dùng §7; property thiếu là finding, không phải “nice to have”.
- **QC:** chỉ chạy khi operator yêu cầu.

Property test là **bằng chứng code**, không phải bằng chứng Done. Human vẫn ký `Done`.
