# 16 — Host placement roadmap (P0–P5)

> **WBS = từ điển** (R05): không theo dõi tiến độ/status. Trạng thái thực thi nằm ở Jira/gate.

> Implementation plan for the ESO sidecar/host split. ESO remains config + observatory; the host owns
> prompt, execution, model selection, workspace and evidence. This plan contains no ESO run/execution
> surface.

## 1. Order decision

```text
1. P0  bugfix + baseline
2. P1  architecture: host vs runtime + hostType
3. P2  contracts: config snapshot + host auth + observation
4. P3  host entrypoint + Mode A
5. P4  Mode B
6. P5  hardening
```

Do **not** start Mode A/B before P1. Mode A/B built on `host_id = runtime` will need a full rework.

## 2. Baseline

Implemented:

```text
global host runtime registry
worker host placement policy
flow config editor/publish/default

ESO no run/execution API

```

```text
knowledge_worker_execution → knowledge_worker_host_policy

WorkerExecutionDto → WorkerPlacementDto

```

```text

```

## 3. Decisions to lock before P1

| ID | Decision | Recommended |
|---|---|---|
| D1 | Host identity | `host = machine/instance`, `runtime = Cursor/AGY/DSH/...` |
| D2 | Runtime identity | `runtimeKey = hostId:runtimeId` |
| D3 | Host binding target | `hostId` (developer × host × stack) |
| D4 | Worker placement target | `allowedHosts[] = runtimeKey` |
| D5 | Model selection | host resolves `modelTier` from its own model catalog |
| D6 | Observation unit | host-generated observation, not ESO run/step |
| D7 | Mode B transport | job envelope + auth first; SSH/CLI fallback |
| D8 | ESO read auth | host read token scoped to consumer + runtime |

## 4. Phase map

| Phase | Goal | Est. | Depends | Exit |
|---|---|---|---|---|
| P0 | close small bugs, freeze baseline | 0.5–1d | now | gates + live smoke |
| P1 | host vs runtime identity | 2–3d | P0, D1–D4 | one host, many runtimes |
| P2 | config snapshot, host auth, observations | 2–3d | P1 | host reads one snapshot; activity visible |
| P3 | host entrypoint + Mode A | 3–5d | P2, D5 | SLP flow on one host |
| P4 | Mode B | 3–5d | P3, D7 | remote worker + evidence |
| P5 | hardening | 1–2d | P4 | offline, retry, audit |

## P1 — Architecture: host vs runtime

### P1.1 Schema

```text
platform.host
  host_id        text PK
  host_type      text not null
  label          text
  created_at     timestamptz
  updated_at     timestamptz

platform.host_runtime
  host_id        text not null references platform.host(host_id) on delete cascade
  runtime_id     text not null
  runtime_kind   text not null check (ide-native|cli|acp)
  models         jsonb not null default '[]'
  default_model  text not null default ''
  lead_eligible  boolean not null default false
  health         text not null default 'unknown'
  last_heartbeat timestamptz
  created_at     timestamptz
  updated_at     timestamptz
  primary key (host_id, runtime_id)
```

### P1.2 Migration

```text
old platform.host_runtime row
  → platform.host(host_id, host_type inferred from runtimeId)
  → platform.host_runtime(host_id, runtime_id, ...)
```

Rules:

```text
hostType = runtimeId family if unknown
runtimeKey = hostId + ':' + runtimeId
preserve models/default/health/leadEligible/lastHeartbeat
idempotent on rerun
```

AC:

```text
[A1-1] no data loss
[A1-2] same host can have cursor + agy runtimes
[A1-3] rerun migration is idempotent
[A1-4] 22 consumer tables unchanged
```

## 6. Risks

| Risk | Impact | Mitigation |
|---|---|---|

| observation duplicates | MEDIUM | idempotency key + unique index |
| Mode B trust | HIGH | signed job + evidence validation |
| model map inconsistency | MEDIUM | host reports tier_map |
