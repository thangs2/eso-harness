# 16 — Host placement roadmap (P0–P5)

> Implementation plan for the ESO sidecar/host split. ESO remains config + observatory; the host owns
> prompt, execution, model selection, workspace and evidence. This plan contains no ESO run/execution
> surface.
>
> **Status:** DRAFT — P0 not started. Baseline builds are green; host/runtime identity is not fixed yet.

## 1. Order decision

```text
1. P0  bugfix + baseline
2. P1  architecture: host vs runtime + hostType
3. P2  contracts: config snapshot + host auth + observation
4. P3  host entrypoint + Mode A
5. P4  Mode B
6. P5  hardening
```

Do **not** start Mode A/B before P1. Mode A/B built on `host_id = runtime` will need a full rework.

## 2. Baseline

Implemented:

```text
global host runtime registry
worker host placement policy
flow config editor/publish/default
host bindings UI
host models bottom sheet
ESO no run/execution API
ESO no spawn/model call/chat
```

Fixed 2026-11-17:

```text
knowledge_worker_execution → knowledge_worker_host_policy
/worker-execution → /worker-placement
/workers/:id/execution → /workers/:id/placement
WorkerExecutionDto → WorkerPlacementDto
"Execution placement" → "Host placement"
knowledge_index_run → knowledge_index_build
host edit no longer fakes heartbeat
```

Verification baseline:

```text
diff check                 PASS
build-host-trees --check   PASS
check-dual-harness         PASS
CP build                   PASS
UI typecheck               PASS
UI build:ng                PASS
consumer schema            22 tables
```

## 3. Decisions to lock before P1

| ID | Decision | Recommended |
|---|---|---|
| D1 | Host identity | `host = machine/instance`, `runtime = Cursor/AGY/DSH/...` |
| D2 | Runtime identity | `runtimeKey = hostId:runtimeId` |
| D3 | Host binding target | `hostId` (developer × host × stack) |
| D4 | Worker placement target | `allowedHosts[] = runtimeKey` |
| D5 | Model selection | host resolves `modelTier` from its own model catalog |
| D6 | Observation unit | host-generated observation, not ESO run/step |
| D7 | Mode B transport | job envelope + auth first; SSH/CLI fallback |
| D8 | ESO read auth | host read token scoped to consumer + runtime |

## 4. Phase map

| Phase | Goal | Est. | Depends | Exit |
|---|---|---|---|---|
| P0 | close small bugs, freeze baseline | 0.5–1d | now | gates + live smoke |
| P1 | host vs runtime identity | 2–3d | P0, D1–D4 | one host, many runtimes |
| P2 | config snapshot, host auth, observations | 2–3d | P1 | host reads one snapshot; activity visible |
| P3 | host entrypoint + Mode A | 3–5d | P2, D5 | SLP flow on one host |
| P4 | Mode B | 3–5d | P3, D7 | remote worker + evidence |
| P5 | hardening | 1–2d | P4 | offline, retry, audit |

## P1 — Architecture: host vs runtime

### P1.1 Schema

```text
platform.host
  host_id        text PK
  host_type      text not null
  label          text
  created_at     timestamptz
  updated_at     timestamptz

platform.host_runtime
  host_id        text not null references platform.host(host_id) on delete cascade
  runtime_id     text not null
  runtime_kind   text not null check (ide-native|cli|acp)
  models         jsonb not null default '[]'
  default_model  text not null default ''
  lead_eligible  boolean not null default false
  health         text not null default 'unknown'
  last_heartbeat timestamptz
  created_at     timestamptz
  updated_at     timestamptz
  primary key (host_id, runtime_id)
```

### P1.2 Migration

```text
old platform.host_runtime row
  → platform.host(host_id, host_type inferred from runtimeId)
  → platform.host_runtime(host_id, runtime_id, ...)
```

Rules:

```text
hostType = runtimeId family if unknown
runtimeKey = hostId + ':' + runtimeId
preserve models/default/health/leadEligible/lastHeartbeat
idempotent on rerun
```

AC:

```text
[A1-1] no data loss
[A1-2] same host can have cursor + agy runtimes
[A1-3] rerun migration is idempotent
[A1-4] 22 consumer tables unchanged
```

### P1.3 API

```text
GET    /api/v1/hosts
PUT    /api/v1/hosts/:hostId
GET    /api/v1/host-runtimes
PUT    /api/v1/host-runtimes/:hostId/:runtimeId
POST   /api/v1/host-runtimes/:hostId/:runtimeId/heartbeat
GET    /api/v1/consumers/:id/worker-placement
PUT    /api/v1/consumers/:id/workers/:workerId/placement
```

`GET /hosts` returns nested runtimes:

```json
{
  "items": [
    {
      "hostId": "host-mac-01",
      "hostType": "cursor",
      "label": "Mac 01",
      "runtimes": [
        { "runtimeId": "cursor-agent", "runtimeKey": "host-mac-01:cursor-agent", "health": "healthy" }
      ]
    }
  ]
}
```

### P1.4 UI Hosts

Do:

AC:

```text
[A1-5] one host displays multiple runtimes
```

### P1.5 Placement target

## P2 — ESO contracts

### P2.1 Config snapshot

```http
GET /api/v1/consumers/:id/config-snapshot?runtimeKey=...
```

Response:

```json
{
  "version": "sha256",
  "consumer": { "id": "testeso", "root": "/repo" },
  "flow": { "flowId": "...", "version": 1, "nodes": [], "edges": [] },
  "workers": [],
  "workerPlacement": [],
  "hosts": [],
  "hostBindings": [],
  "stackVersion": 1,
  "providerRouting": {}
}
```

Rules:

```text
read-only
no secrets
no run/execution fields
stable hash
ETag/304 support
```

AC:

```text
[A2-1] one request returns full config
[A2-2] same inputs → same hash
[A2-3] host can cache and detect drift
```

### P2.2 Host auth

Do:

```text
host read token scoped consumer + runtimeKey
config read-only
observation write-only
no operator/admin rights
```

AC:

```text
[A2-4] host token cannot write config
[A2-5] host token cannot read other consumers
[A2-6] host token cannot read secrets
```

### P2.3 Observation ingestion

Schema:

```text
knowledge_observation
  observation_id   text PK
  trace_id         text
  host_id          text
  runtime_key      text
  worker_id        text
  event            text
  outcome          text
  evidence         jsonb
  at               timestamptz
  idempotency_key  text unique
```

API:

```text
POST /api/v1/consumers/:id/observations
GET  /api/v1/consumers/:id/observations
```

Rules:

```text
append-only
idempotent
host-reported
no run/step/claim/advance
```

AC:

```text
[A2-7] retry same idempotency key → no duplicate
[A2-8] ESO UI shows observation timeline
[A2-9] no ESO execution concept
```

## P3 — Host entrypoint + Mode A

### P3.1 Host runtime package

Location: **outside** `eso/control-plane`:

```text
host-runtime/
  src/
    entrypoint
    config-reader
    flow-engine
    model-resolver
    worker-policy
    evidence-builder
    observation-writer
    adapters/cursor
    adapters/agy
```

### P3.2 Entrypoint

Define how user prompt activates SLP:

```text
Cursor: rule/hook/agent/command
AGY: agent/command/rule
Claude/Codex/DSH/Paseo/Orca: equivalent
```

AC:

```text
[A3-1] prompt activates entrypoint
[A3-2] entrypoint loads config snapshot
[A3-3] entrypoint selects flow + worker
```

### P3.3 Shared flow library

Do:

```text
extract pure flow evaluation library
host imports it
ESO control plane does not run it
```

AC:

```text
[A3-4] same flow semantics across hosts
[A3-5] no eval inside ESO request path
```

### P3.4 Mode A adapter

Priority:

```text
A3 deterministic CLI first
A1/A2 native subagents second
```

Sequence:

```text
prompt → config → worker → tier → model → adapter → evidence → host flow → observation
```

AC:

```text
[A3-6] same host, different worker models
[A3-7] evidence complete
[A3-8] ESO sees observation only
[A3-9] control plane does not spawn
```

## 6. Risks

| Risk | Impact | Mitigation |
|---|---|---|
| host/runtime migration data loss | HIGH | backup, idempotent migration, test staging |
| runtimeKey format drift | HIGH | lock format in D2 before code |
| host entrypoint differs per host | MEDIUM | define contract per host in P3.2 |
| observation duplicates | MEDIUM | idempotency key + unique index |
| Mode B trust | HIGH | signed job + evidence validation |
| model map inconsistency | MEDIUM | host reports tier_map |
