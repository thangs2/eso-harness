# FRD `F-04` — Vòng đời consumer

**Trace:** `P3` · `P7` → `G-L` → `D4` → `UC-06` · `UC-07` · `UC-08` · `BR-06` · `BR-07` · `BR-15`
**Actor:** A-01 · **Giai đoạn:** Bootstrap

## 1. Đặc tả

| | |
|---|---|
| **Đầu vào** | `POST /api/v1/consumers/<id>/retire` · `/reactivate` · `/delete` · `/restore` · `/purge` (body `confirm_id`) |
| **Đầu ra** | record với `status` mới + event tương ứng |
| **Luật** | `BR-06` · `BR-07` · `BR-15` |

## 2. State machine

```text
ready ⇄ retired          (dữ liệu giữ nguyên; data route 404 khi retired)
ready|retired → deleted  (soft: ẩn list mặc định, giữ schema + file, restore được)
deleted → ready          (restore)
deleted|retired → purged (DROP SCHEMA CASCADE + xoá file generated + status=purged)
```

## 3. Xử lý

1. `retire`/`delete`: chỉ từ `ready` (hoặc `retired` cho `delete`); ghi event; **không** xoá dữ liệu.
2. `restore`: chỉ từ `deleted`; status → `ready`; materialize lại nếu file thiếu.
3. `reactivate`: chỉ từ `retired`; status → `ready`.
4. `purge`: chỉ từ `deleted`/`retired`; bắt buộc `confirm_id == id`; trong transaction: `DROP SCHEMA c_<id> CASCADE`, xoá `.harness/config.json` **chỉ khi** có header generated, `status=purged`, ghi event `purged`.
5. Mọi chuyển trạng thái trả record mới; không trả dữ liệu đã xoá.

## 4. Từ chối

| Mã | Khi |
|---|---|
| `CONSUMER_NOT_FOUND` | id không tồn tại / đã `purged` |
| `INVALID_STATE` | transition không hợp lệ (vd purge từ `ready`) |
| `PURGE_CONFIRM_MISMATCH` | `confirm_id` ≠ `id` |

## 5. Dữ liệu chạm

`platform.consumer` (status) · `platform.consumer_event` (retired/reactivated/deleted/restored/purged) · schema `c_<id>` (chỉ purge) · `.harness/config.json` (chỉ purge).

## 6. Phi chức năng

- Purge **không hoàn tác**; UI phải hỏi xác nhận + gõ lại id.
- `purged` record vẫn còn trong registry (audit), không hiện ở list mặc định.
- Không auto-purge theo thời gian ở Bootstrap.
