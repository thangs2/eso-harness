# FRD `F-05` — Profile một nguồn + drift

**Trace:** `P3` · `P7` → `G-D` · `G-N` → `D4` → `UC-05` · `BR-03` · `BR-04`
**Actor:** A-01 (qua UI/CLI) · **Giai đoạn:** baseline

## 1. Đặc tả

| | |
|---|---|
| **Đầu vào** | record consumer trong DB · `root` trên đĩa |
| **Đầu ra** | `<root>/.harness/config.json` — artifact sinh ra, kèm `materialized_hash` trong DB |
| **Luật** | `BR-03` (DB là nguồn) · `BR-04` (drift phải bị phát hiện) |
| **Lệnh** | `eso consumer materialize <id>` · `eso consumer check <id>` |

## 2. Định dạng file sinh ra

```json
{
  "_generated": "generated by eso — do not edit",
  "_schema": 1,
  "id": "<consumer-id>",
  "name": "...",
  "root": "...",
  "sdlcRoot": "...",
  "profile": { "...": "..." },
  "zones": [ ... ],
  "hash": "<sha256 của nội dung không gồm dòng _generated/hash>"
}
```

## 3. Xử lý

1. Materialize: dựng JSON chuẩn hoá (thứ tự key cố định) → ghi file tạm cùng thư mục → `rename` (nguyên tử) → tính `materialized_hash` → lưu DB.
2. Check (trả `status` ∈ `ok`·`drift`·`missing`·`invalid`): đọc file; thiếu ⇒ `missing`; parse lỗi ⇒ `invalid`; tính hash; so `materialized_hash` ⇒ `ok` / `drift`.
3. `drift`: **không** tự ghi đè; trả về diff ngắn (trường nào khác) để operator quyết.
4. `materialize` khi DB là nguồn: luôn ghi đè file, kể cả khi file bị sửa tay.

## 4. Từ chối

| Mã | Khi |
|---|---|
| `ROOT_NOT_FOUND` | root không còn tồn tại khi materialize |
| `PROFILE_DRIFT` | `check` thấy file khác DB (kèm `expected`/`actual` hash) |
| `PROFILE_INVALID` | file sinh ra không parse được |

## 5. Dữ liệu chạm

`platform.consumer.materialized_hash` · `<root>/.harness/config.json`.

## 6. Phi chức năng

- Ghi nguyên tử: không bao giờ để file nửa vời.
- Header `_generated` là điều kiện để purge được phép xoá file (F-04).
- baseline chỉ sinh `config.json`; hook/turn files thuộc Expansion.
