# FRD `F-09` — Verdict trước khi thực thi

**Trace:** `P4` → `G-K` → `BR-10` · `BR-11` · `UC-10`
**Actor:** A-01 · A-02 · **Giai đoạn:** GĐ2

## 1. Đặc tả

| | |
|---|---|
| **Đầu vào** | `(actor, task, evidence_pack)` — mô tả việc + bằng chứng hiện có |
| **Đầu ra** | `verdict = { level, basis, requirements[], missing[], mode }` — **trước** khi ghi bất kỳ file nào |
| **Luật** | `BR-10` (false-allow tệ hơn false-deny) · `BR-11` (gate phải mở được) |
| **Trạng thái** | `sufficient` · `partial` · `insufficient` · `cannot-judge` |

## 2. Xử lý

1. Dẫn xuất `requirements[]` từ 4 nguồn: `bar` (chuẩn) · `work` (việc) · `blast` (phạm vi ảnh hưởng) · `declared` (khai báo); mỗi đòi hỏi phải nêu nguồn (INV-ESO-03).
2. Đối chiếu từng đòi hỏi với `evidence_pack`; đạt/không đạt, kèm bằng chứng.
3. `level` = mức thấp nhất trong các đòi hỏi; `basis` = nguồn yếu nhất trong các answer đạt.
4. `mode` suy từ `level × permission × escalation` — **không** bao giờ tự ra `permitted` khi `cannot-judge`.
5. Trả verdict **trước**; ghi file chỉ khi `mode` cho phép.

## 3. Từ chối

| Mã | Khi |
|---|---|
| `INVALID_TASK` | task/requirements không dựng được từ 4 nguồn |
| `NEEDS_APPROVAL` | `mode=ask` và cần người quyết |
| `FORBIDDEN_ACTOR` | actor không có quyền yêu cầu verdict |

## 4. Dữ liệu chạm

Verdict record (append-only, schema consumer) · evidence ledger (F-11).

## 5. Phi chức năng

- Verdict phải **tái lập được**: cùng input ⇒ cùng output (trừ `at`).
- Không kết luận `sufficient` khi thiếu `basis` (INV-ESO-01).
