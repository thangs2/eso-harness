# FRD `F-06` — Cô lập consumer

**Trace:** `P3` → `G-L` → `D6` → `UC-09` · `BR-01` · `BR-02`
**Actor:** hệ thống · **Giai đoạn:** GĐ1

## 1. Đặc tả

| | |
|---|---|
| **Đầu vào** | request tới `/api/v1/c/<consumer>/…` (mọi phương thức) |
| **Đầu ra** | request được chạy trong đúng schema của consumer, hoặc bị từ chối |
| **Luật** | `BR-01` · `BR-02` · không fallback `public` |

## 2. Xử lý (middleware)

1. Lấy `<consumer>` từ **đường dẫn**; không nhận từ body/query.
2. Validate slug; sai ⇒ `400 INVALID_CONSUMER_ID` (không chạm DB bằng tên schema do client ghép).
3. Tra `platform.consumer WHERE id = $1`; không có hoặc `status ∉ {ready}` ⇒ `404 CONSUMER_NOT_FOUND` (cùng thông điệp với "không tồn tại").
4. Mở transaction; `SET LOCAL search_path = c_<id>, platform, public`.
5. Chạy handler; commit/rollback; trả connection (search_path không rò sang request sau).
6. Mọi query trong handler **không** tự ghép tên schema; nếu cần `platform` thì định danh đủ.

## 3. Từ chối

| Mã | Khi |
|---|---|
| `INVALID_CONSUMER_ID` | slug sai |
| `CONSUMER_NOT_FOUND` | không tồn tại · `retired` · `deleted` · `purged` |

## 4. Dữ liệu chạm

`platform.consumer` (read) · schema `c_<id>` (mọi bảng của consumer).

## 5. Test bắt buộc (6 case)

1. Dữ liệu của A không thấy qua route B.
2. Path injection (`../b`, `c_b`, `%2e%2e`) ⇒ 400/404, không chạm DB.
3. Consumer không tồn tại/retired ⇒ 404, cùng message.
4. Pool leak: A rồi B trên cùng connection ⇒ B thấy B.
5. Chuỗi A→B→A→B ổn định.
6. Cleanup: drop schema sau test; chạy lại nhiều lần không rác.

## 6. Phi chức năng

- `public` để trống: quên `search_path` ⇒ lỗi "relation does not exist", **không** trả dữ liệu người khác.
- Fail-closed: thiếu `platform.consumer` ⇒ 404, không tự tạo schema.
