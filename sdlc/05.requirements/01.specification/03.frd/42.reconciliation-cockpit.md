# `42` — Unified Reconciliation Cockpit (Code ↔ Artifacts/SDLC ↔ PostgreSQL)

> **Lưu ý PRD (`OPEN-RECONCILIATION-PRD`):** Tài liệu này chuẩn hóa đặc tả chức năng cho năng lực Reconciliation Cockpit đã triển khai thực tế tại `/consumers/:id/reconciliation`. Việc gán mã `F-nn` chính thức trong [`01.prd/03.capabilities.md`](../01.prd/03.capabilities.md) đang ở trạng thái `OPEN` chờ operator chốt.

## 1. Tóm tắt & Vai trò

Cung cấp bề mặt và engine **hòa giải ngược 3 trụ cột** cho từng consumer: phát hiện sai lệch giữa **Source Code** (`GAP-A`, `GAP-B`, `GAP-D`), **Artifacts · SDLC · Rules** (`GAP-C`, `GAP-E`), và **PostgreSQL `knowledge_doc`** (`GAP-F`), đồng thời bảo vệ **Gate S17** (*không bao giờ tự động phê duyệt bản nháp sinh ngược*).

---

## 2. Đầu vào (Inputs)

| Endpoint | Tham số / Body | Ràng buộc |
|---|---|---|
| `POST /api/v1/consumers/:id/reconciliation/scan` | `:id` (consumer id), `{ scope?: 'full' \| 'git-diff' }` | `requireAuth`; `scope` mặc định `'full'` |
| `GET /api/v1/consumers/:id/reconciliation/gaps` | `:id` (consumer id) | `requireAuth` |
| `POST /api/v1/consumers/:id/reconciliation/ignore` | `{ gapId: string, filePath?: string, symbol?: string, reason?: string }` | `requireAuth`; `gapId` bắt buộc không rỗng |
| `POST /api/v1/consumers/:id/reconciliation/relock` | `{ gapId: string, filePath: string }` | `requireAuth`; `filePath` phải là relative path nằm trong `consumer.root` |
| `POST /api/v1/consumers/:id/reconciliation/sync-index` | `:id` (consumer id) | `requireAuth` |
| `POST /api/v1/consumers/:id/artifacts` | `IngestArtifactInput` (`ktState: 'proposed'`, `origin: 'agent'`) | `requireAuth`; chỉ tạo draft ở trạng thái `proposed` |

---

## 3. Xử lý (Processing Rules)

1. **Consumer-Scoped Scan (`scan`):**
   - Nạp `consumer.root` từ `PlatformStore`; dùng chung `listIndexableMarkdownFiles(root)` với `KnowledgeIndexService` để bảo đảm 100% đồng nhất tập file và real disk casing giữa Disk và PostgreSQL (`knowledge_doc`).
   - Áp dụng danh sách loại trừ mặc định (`/health`, `/healthz`, `/metrics`, `_prisma_migrations`, `schema_migrations`) và `.harness/reconcile-ignore.json`.
   - Sinh deterministic `gapId` theo `gap-${type}-${sha256(filePath + ':' + symbol).slice(0, 10)}` và đồng bộ trạng thái (`open` | `staged_in_inbox` | `resolved`) từ bảng `consumer_artifacts` (`proposed` → `staged_in_inbox`, `approved` → `resolved`).
   - Khi `scope === 'git-diff'`, chỉ quét file thay đổi/untracked từ `git status --porcelain -uall` & `git diff --name-only HEAD` (fallback về `'full'` nếu không phải git repo).
2. **Gate S17 Staging (`Extract Draft` / `Generate Skeleton`):**
   - Tuyệt đối không ghi trực tiếp vào `sdlc/` và không tự duyệt (`ktState` luôn là `'proposed'`, `metadata.originType: 'reverse-extraction'`).
   - Chỉ khi operator bấm **Promote to KB** trong Artifacts Inbox (`ArtifactLifecycleService.promote`), hệ thống mới kiểm tra an toàn đường dẫn (chỉ cho phép ghi dưới `sdlc/`), ghi file xuống đĩa, cập nhật `.harness/knowledge-manifest.json`, và kích hoạt `knowledgeIndex.index()`.
3. **Re-lock Hash (`GAP-C`):** Tính lại SHA-256 trên đĩa, cập nhật atomic vào `.harness/knowledge-manifest.json`, gọi `knowledgeIndex.index()` và đánh dấu `resolved`.
4. **Sync DB (`GAP-F`):** Gọi `knowledgeIndex.index(consumerId)` rồi chạy lại `scan(consumerId, { scope: 'full' })`.

## 4. Từ chối & Mã lỗi (Rejections)

| Điều kiện | HTTP | Mã lỗi |
|---|---|---|
| Thiếu hoặc sai token xác thực | `401` | `UNAUTHORIZED` |
| `:id` không hợp lệ hoặc consumer không tồn tại / đã `purged` | `404` | `CONSUMER_NOT_FOUND` |
| `relock` với `filePath` chứa `..`, đường dẫn tuyệt đối hoặc ngoài `consumer.root` | `400` | `INVALID_INPUT` |
| `ignore` thiếu `gapId` hoặc `relock` trỏ tới file không tồn tại trên đĩa | `400` / `404` | `INVALID_INPUT` / `NOT_FOUND` |
