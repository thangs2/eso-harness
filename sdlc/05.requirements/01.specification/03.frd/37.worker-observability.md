# FRD `F-42` — Worker execution observability

**Trace:** `P4` · `P7` → `G-V` → `BR-46` · `BR-12`

> **Phân tách subject trong cùng một F:** §1–§6 = **cơ chế** (event envelope · 2D/3D); §7 = **bề mặt** `/observatory`.
> Theo luật phòng *"mỗi `F-nn` một file"* ([`00.index`](00.index.md)) nên bề mặt nằm cùng file, không tách file thứ hai.
**Actor:** A-01 operator · A-04 auditor · **Giai đoạn:** Phase 2 · `D17`

## 7. Bề mặt `/observatory` — `PAGE-OBS` (cùng `F-42`, không phải F mới)

> Bề mặt là **một phần** của năng lực `F-42`; đặt ở đây để giữ luật phòng *"mỗi `F-nn` một file"*
> ([`00.index`](00.index.md) luật 1). Chi tiết khác có nhà riêng: `REQ-47` (SRS) · `US-OBS-01` · `AC-OBS-01` · `SCN-OBS-01` · ma trận truy vết (`06.analysis/04.rtm/`) · bề mặt UI (`08.ui-design/20.pages/01.observatory.md`).

| | |
|---|---|
| **Actor** | `A-01` operator (chính) · `A-04` auditor (đọc) |
| **Đầu vào** | `consumer` id (`?consumer=` hoặc chọn trong ngữ cảnh) · tuỳ chọn `?trace=` để phát lại |
| **Đầu ra** | 5 khối: ngữ cảnh consumer (read-only) · KPI · đồ thị worker · live pulse · bảng request |
| **Luật** | `BR-46` · `BR-12` · `BR-05` |
| **Trạng thái** | `idle` (chưa chọn consumer) · `loading` · `ready` · `empty` · `playing` · `error` |

**Xử lý**

1. Chọn consumer theo `?consumer`; thiếu/không hợp lệ xử lý theo mục **Khi từ chối** dưới đây; ghi lựa chọn vào URL.
2. Tải ngữ cảnh: consumer · root · status + version · consent · flow + version. Chỉ hiển thị.
3. Chọn flow: `isDefault` → `published` → flow đầu tiên. Không có tương tác đổi flow.
4. Tính KPI: tổng event · số trace · số prompt đã submit · số fail/block · event mới nhất.
5. Dựng đồ thị từ flow; node mang event/failure, cạnh mang số chuyển tiếp liên tiếp trong trace.
6. Phát lại một lượt: khớp chính xác `traceId` trước, rồi khớp chuỗi trên worker/event/outcome/evidence.
7. Lọc theo worker đang chọn; chọn node trung tâm ⇒ bỏ lọc.
8. Bảng request: lọc chuỗi/host/failure · nhóm conversation · phân trang · mở prompt con.
9. Điều hướng sang event stream / 3D view / chi tiết request, luôn mang consumer.
10. Tải lại toàn bộ ngữ cảnh; không có trạng thái ghi.

**Khi từ chối** — mã định nghĩa ở SRS `04` §6, ở đây chỉ nêu **khi nào**:
`?consumer` không tồn tại ⇒ `OBS_CONSUMER_UNKNOWN` · tải dữ liệu lỗi ⇒ `OBS_UPSTREAM_FAILED` ·
không có flow ⇒ `OBS_FLOW_MISSING` (rỗng, không lỗi) · ô phát lại rỗng ⇒ `OBS_QUERY_EMPTY` ·
không khớp trace ⇒ `OBS_TRACE_NOT_MATCHED` · trace rỗng ⇒ `OBS_TRACE_EMPTY` · 401/403 ⇒ `OBS_DENIED`.

**Endpoint (trỏ, không chép):** SRS [`04` §6](../04.srs/04.external-interfaces.md) #1…#8.

**Không làm:** sửa cấu hình consumer · quản lý flow · 3D event graph (Phase 2) · hiện prompt body/secret ·
tổng hợp cross-consumer · phân quyền per-consumer (`OPEN-OBS-ACL`).

**Đã chốt 2026-11-23:** KPI nhãn `Prompts` (event `prompt.submitted`), bảng giữ `Requests` (1 trace = 1 request) ·
không UI chọn flow · `denied` = 401/403 · chỉ một log `knowledge_observation`.
