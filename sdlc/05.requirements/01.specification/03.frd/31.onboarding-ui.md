# FRD `F-31` — Onboarding UI

**Trace:** `P3` · `P4` → `G-R` → `BR-26` · `BR-27` · `BR-30`
**Actor:** A-01 operator · **Giai đoạn:** Phase 1 · `D5`

## 1. Đặc tả

| | |
|---|---|
| **Đầu vào** | consumer được chọn từ danh sách; root repo |
| **Đầu ra** | request provision + trạng thái provision hiển thị/read-back |
| **Luật** | `BR-26` (provision), `BR-27` (select consumer), `BR-30` (info) |
| **Trạng thái** | select · preview · provisioning · ready · error |

## 2. Luồng

1. **Select consumer**: dropdown/list consumer `ready`; không tạo mới nếu đã có.
2. **Review**: hiện consumer id/name/root, material bundle, schema `c_<id>`.
3. **Preview**: hiện việc sẽ provision; chưa ghi.
4. **Apply**: gọi provisioning F-32.
5. **Status**: hiện schema/material/info; lỗi mã + message; retry.

## 3. Từ chối

| Mã | Khi |
|---|---|
| `CONSUMER_NOT_FOUND` | consumer không tồn tại |
| `INVALID_STATE` | consumer không `ready` |
| `ROOT_NOT_FOUND` | root không tồn tại |
| `PROVISION_FAILED` | BE provision lỗi (surface nguyên văn) |

## 4. Dữ liệu chạm

UI state; gọi F-32. Không tự ghi file/schema từ FE.

## 5. Phi chức năng

- Không có field host/source/tier/recipe.
- Không tự tạo consumer nếu đã có.
- Hiển thị trạng thái thật từ BE; không báo “xong” trước read-back.

## 7. Bề mặt `/onboarding` — `PAGE-ONBOARD` (C0–C6 + reverify)

**Chain:** US-39 · AC-39-1…3 · SCN-39 · RTM-ONBOARD-01

> Cùng `F-31`; UI [`14.onboarding`](../../../08.ui-design/20.pages/14.onboarding.md). Nguồn: `onboarding.page.ts`, `onboarding.service.ts`.

| | |
|---|---|
| **Actor** | A-01 |
| **Đầu vào** | consumer `status === 'ready'` (auto-select consumer đầu tiên) |
| **Đầu ra** | preview schema `c_<id>` + material 4 mục; provision; success/error |

### 7.1 Xử lý (as-is)

1. Tải consumer, **chỉ giữ `ready`**; tự chọn consumer đầu tiên; đổi select ⇒ reset preview/success/error.
2. Preview 5 field: `Consumer` · `Display name` · `Schema` (`c_<id>`) · `Material` (4 mục) · `Root`.
3. `Confirm & provision` (không phải "Provision") — gọi `POST .../provision`; chuỗi 5 bước hiển thị; nút disabled khi `submitting`.
4. Thành công: banner `Provisioning complete` + `res.status` + "…was provisioned with schema … and is ready".
5. Lỗi: `code` + HTTP status (optional) + message; mã UI tự đặt `LOAD_FAILED`/`PROVISION_FAILED` khi không có code từ server.
6. Rỗng: panel `role="status"` + CTA sang `/setup` (không chặn điều hướng).

**Caveat read-back:** service có gọi `GET .../setup` và trả `ready`, nhưng template **không dùng** `res.ready` — câu "and is ready" in bất kể giá trị ⇒ `OPEN-ONBOARD-READBACK`.
