# FRD `F-03` — Registry consumer

**Trace:** `B-00` → `G-L` → `D3` → `UC-03` · `UC-04` · `BR-09`
**Actor:** A-01 · **Giai đoạn:** baseline

## 1. Đặc tả

| | |
|---|---|
| **Đầu vào** | `GET /api/v1/consumers` (filter `status`, `include_deleted`) · `GET /api/v1/consumers/<id>` · `PUT /api/v1/consumers/<id>` (body profile + `expected_version`) |
| **Đầu ra** | danh sách/chi tiết record; update trả `version+1` |
| **Luật** | `BR-09` (optimistic lock) · `BR-06` (ẩn `deleted` mặc định) |

## 2. Xử lý

1. List: đọc `platform.consumer`; mặc định loại `deleted` và `purged`; `retired` vẫn hiện; sắp theo `updated_at` giảm dần.
2. Detail: trả toàn bộ trường + `profile` + `materialized_hash`; không trả credential/DSN.
3. Update:
   1. kiểm `expected_version` = `version` hiện tại, nếu khác ⇒ `409 STALE_VERSION`;
   2. validate body như F-02 (trừ `id`);
   3. update trong transaction: `version+1`, `updated_at`, ghi event `updated`;
   4. materialize lại file + cập nhật hash (F-05).
4. Không có endpoint xoá cứng; xoá thuộc F-04.

## 3. Từ chối

| Mã | Khi |
|---|---|
| `CONSUMER_NOT_FOUND` | id không tồn tại / `retired` / `deleted` (cùng thông điệp) |
| `STALE_VERSION` | `expected_version` khác hiện tại |
| `MATERIALIZE_FAILED` | ghi file lỗi sau commit |

## 4. Dữ liệu chạm

`platform.consumer` (read/update) · `platform.consumer_event` (`updated`) · `<root>/.harness/config.json`.

## 5. Phi chức năng

- Update là **idempotent theo version**: gửi lại cùng `expected_version` sau khi thành công ⇒ `STALE_VERSION`.
- Hai tab sửa cùng lúc: một thắng, một `STALE_VERSION` — không mất thay đổi im lặng.
- `id` bất biến; nếu body có `id` khác ⇒ `400 INVALID_CONSUMER_ID`.
