## 2. Thứ tự đọc

> Đầu chuỗi nằm ngoài thư mục này: **vision · mission** ở [`03.inception/01.vision`](../../03.inception/01.vision/01.vision-mission-goals.md).

```text
pain point · vision   vì sao tồn tại, đi đâu              (03.inception)
 └─ BRD   ai đau · luật · quyền · use case               (02.brd)
     └─ PRD  năng lực · phạm vi release · metric          (01.prd)
         └─ FRD  1 file / năng lực: vào · ra · từ chối    (03.frd)
             └─ SRS  REQ + giao diện ngoài + ràng buộc + đường kiểm
                 └─ US/AC  tiêu chí nghiệm thu             (06.analysis)
                     └─ technical planes B/C/D + UI        (07.technical · 08.ui-design)
                         └─ WBS slice (leaf)               (09.wbs)
                             └─ BIP/FIP packet / slice     (09.wbs/01.packets)
                                 └─ SCN (planned) → code → SCN run → DoD
```

**Ba luật của chuỗi này:**

1. **Jira ticket sinh từ `AC` + packet**, không sinh từ FRD/SRS. Ticket không có slice id thì chưa đủ để build.
2. **WBS trước packet**: packet cần `slice id`; slice id chỉ tồn tại trong WBS. Viết packet trước WBS = bịa id.
3. **Packet chỉ để `READY-to-implement`**, không phải "đã xong". `Done` do người ký (BR-05).

## 3. Vì sao sharded

Luật của cây: **một sự thật, một chỗ**. Hub giữ **câu hỏi** và **đường dẫn**; phát biểu nằm ở shard sở hữu. Ngoại lệ duy
nhất là NFR — nó chưa từng tồn tại ở đâu khác, nên `05.nfr-spec` **là** nguồn.

## 4. Điều kiện để gọi là "đầy đủ"

| Loại | Đầy đủ khi |
|---|---|
| PRD | mọi mục có nội dung hoặc `OPEN`; mọi goal có **một** chỉ số |
| BRD | mọi `BR` có shard; mọi actor có quyền **và** điều bị cấm; mọi `UC` có narrative |
| FRD | mọi chức năng có **file**; mọi file nêu **≥ 1** điều kiện từ chối |
| SRS | mọi `REQ` có đường kiểm |
| NFR-spec | mọi `NFR` có **ngưỡng** **và** **cách đo** |
