# `02` — Từ vựng

Chỉ định nghĩa từ **được dùng trong** REQ/API/DB. Từ không dùng thì không có ở đây.

| Từ | Nghĩa trong ESO |
|---|---|
| **Consumer** | Một đối tượng thụ hưởng (repo/đội) do operator đăng ký; có `id`, `root`, schema riêng. **Không** phải tenant, không phải user. |
| **Beneficiary** | Kết quả GĐ1: consumer thật đã đăng ký + có dữ liệu trong DB. |
| **Operator (A-01)** | Người duy nhất ở GĐ1: đăng nhập, đăng ký consumer, ký `Done`, duyệt tri thức. |
| **Registry** | `platform.consumer` + `platform.consumer_event` — sổ đăng ký consumer. |
| **Profile** | Cấu hình của consumer (id, root, sdlcRoot, zones…), **DB là nguồn**. |
| **Artifact sinh ra** | `.harness/config.json` — bản chiếu profile, có header `generated by eso`; sửa tay = drift. |
| **Drift** | File artifact khác DB (`materialized_hash`). |
| **Schema-per-consumer** | Cách cô lập: mỗi consumer một schema `c_<id>` trong cùng DB (`D-110`). |
| **search_path** | Biến phiên Postgres được set `c_<id>, platform, public` **trong transaction** của request. |
| **Soft delete** | Ẩn consumer khỏi danh sách mặc định nhưng **giữ** schema + file; còn `restore`. |
| **Purge** | Xoá hẳn: `DROP SCHEMA` + xoá file generated; giữ record audit `purged`; phải gõ lại id. |
| **Verdict** | `level · basis · requirements · missing · mode` — phán quyết "đủ/chưa đủ" **trước** khi ghi. |
| **Basis** | Nguồn yếu nhất trong các answer đạt (`bar` · `work` · `blast` · `declared`). |
| **Evidence** | Bản ghi bằng chứng append-only, có `kind` + `source` + `at` + `hash`. |
| **Kind** | Loại tri thức/artifact bắt buộc của consumer (template do consumer khai). |
| **Owner** | Người chịu trách nhiệm một artifact/kind (A-08 custodian). |
| **Sufficiency** | Đánh giá đủ/thiếu **nội dung**: `MISSING_KIND` · `NEAR_DUPLICATE` · `CONTENT_CONTRADICTS` · `STALE` · `OWNER_MISSING`. |
| **Freshness** | "Còn hiện hành": `current · stale · unknown` + lý do. |
| **allowed_files / forbidden** | Scope ghi của actor; kiểm **trước** khi ghi. |
| **Slice** | Một leaf work package của WBS; đơn vị để viết BIP/FIP packet. |
| **BIP / FIP** | Backend / Frontend Implementation Packet — một packet mỗi slice, chỉ để `READY-to-implement`. |
| **REQ / AC / SCN** | Yêu cầu hệ · tiêu chí nghiệm thu · kịch bản kiểm. |
| **NFR** | Yêu cầu phi chức năng **có ngưỡng** (thuộc `05.nfr-spec`). |
