# `06` — Đường kiểm

Trả lời: **mỗi REQ được kiểm ở đâu**, và **baseline xong nghĩa là gì**.

## 1. Bốn tầng ki

| Tầng | Ki gì | Công cụ | Chạy khi |
|---|---|---|---|
| **L1 unit** | hàm thuần: validate, hash, state machine, chọn tri thức | `bun test` (không DB) | mỗi thay đổi |
| **L2 integration** | API + registry + schema + file, với **Postgres thật** local | `bun test` + `ESO_TEST_DB_URL` | mỗi thay đổi chạm DB/API |
| **L3 E2E** | kịch bản 9 bước beneficiary, JSON report, exit code | script `eso/e2e` | trước khi tuyên bố baseline xong |
| **L4 smoke tay** | operator dùng UI thật, có screenshot | người | 1 lần cho baseline |

**Không** tầng nào thay tầng khác: L1 xanh không chứng minh cô lập; L3 xanh không chứng minh operator dùng được.

## 5. Thứ tự thực thi (không đảo)

```text
REQ → US/AC (06.analysis) → technical planes B/C/D + UI → WBS slice
    → BIP/FIP packet (§9 READY) → SCN planned → code (tdd-unit RED → impl GREEN)
    → chạy SCN → DoD → người ký Done
```

`SCN` **viết trước** code nhưng **chạy sau** impl; packet đòi "test đã chạy" để `READY` là **đảo thứ tự** (`D-81`).
