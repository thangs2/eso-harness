# `07` — Harness settings: bản ghi yêu cầu của operator

**Trạng thái:** DRAFT — bản ghi yêu cầu, chưa phải FRD/SRS.
**Ngày ghi:** 2026-11-11.
**Nguồn:** operator mô tả trực tiếp trong phiên review UI settings.

File này ghi **điều operator mong đợi**, không ghi giải pháp UI cuối cùng. Mọi diễn giải thêm phải ghi rõ là diễn giải.

## 0. Chốt mô hình — 2026-11-11

Operator xác nhận:

> **"Đây là lắp ghép một harness stack và gán stack đó cho từng host profile."** — đúng.

Từ đây dùng các định nghĩa:

| Khái niệm | Nghĩa |
|---|---|
| **Harness stack** | Một stack 7 layer thuộc consumer/repo; là canonical. |
| **Host profile** | Một cặp `(dev, host)` được gán stack; có thể override từng layer. |
| **Stack assignment** | Gán một stack version cho một host profile; không copy stack. |
| **Layer binding** | Quyết định layer đó lấy từ ESO / host / market / file material / off. |

### 0.1 Không áp đặt lựa chọn của người dùng

Host profile là **lựa chọn của người dùng**, không phải policy sản phẩm.

Mỗi dev/QC/operator được tự chọn:

```text
host nào
bao nhiêu host
stack nào
layer nào override
market provider nào
```

Sản phẩm **không** quy định:

```text
DEV_2 phải dùng market
DEV_1 phải dùng ESO
QC phải dùng host nào
```

Các bảng `DEV_1/DEV_2/DEV_3` trong file này chỉ là **ví dụ minh hoạ**, không phải
ma trận bắt buộc.

### 0.2 Nguyên tắc plugin-able

Đây là keyword trung tâm, không phải chi tiết phụ.

Toàn bộ harness phải **plugin-able** ở cả hai chiều:

```text
ESO cắm vào host        → host adapter/plugin
Host/source cắm vào ESO → plugin provider
```

Cụ thể:

| Thành phần | Plugin-able |
|---|---|
| Host | Cursor · AGY · Claude · Codex · DSH · Paseo · Orca |
| Harness source | market · eso-native · host-native |
| Memory provider | agentmemory · native ESO · host memory |
| Code graph provider | codegraph · native ESO · host graph |
| Document graph | ESO plugin/provider |
| MCP | `mcp.json` · `mcp_config.json` · DSH/Paseo/Orca plugin |
| Multi-agent worker | role/worker plugin |
| Hooks | host hook plugin |

Luật:

1. Không hardcode danh sách host/provider trong UI.
2. Không hardcode `if host === cursor`.
3. Plugin khai manifest: id · type · version · capability · config schema · UI schema.
4. UI đọc plugin registry và render cấu hình tương ứng.
5. Host profile trỏ tới plugin id, không trỏ tới code.
6. Plugin thiếu capability phải hiện warning, không giả vờ đủ.

Hệ quả:

- Stack là **một** trên repo.
- Host profile là **nhiều**.
- Profile **trỏ** tới stack, không sở hữu bản sao.
- Mỗi layer có thể override theo profile.
- Host không phải field của consumer.
- Không có product tier/edition.

### 0.3 Non-invasive và federated ownership

Operator chốt:

> ESO **không thể ép** người dùng chỉ dùng ESO. ESO phải theo host/tool hiện có.

Ba bất biến:

1. **Optionality**: gỡ ESO, host vẫn làm việc. Dev dùng tool bất kỳ ngoài danh sách vẫn làm việc bình thường.
2. **Non-invasive**: ESO không ghi đè config host; chỉ ghi file/block có marker ESO.
3. **Unknown is valid**: host/tool không được ESO hỗ trợ vẫn hợp lệ; ESO ghi `unknown`, không fail.

#### Ownership matrix

| Artifact | Owner / SoT | Vai trò | ESO được ghi? |
|---|---|---|---|
| `.harness/` | **ESO** | canonical state của ESO | có |
| `AGENTS.md` canonical block | **ESO** | material entry | chỉ block có marker |
| `agents/` material | **ESO** | canonical material | file có marker |
| `.cursor/` | **Cursor** | host runtime/config | chỉ projection có marker |
| `.agents/` | **AGY** | host runtime/config | chỉ projection có marker |
| `.claude/` | **Claude** | host runtime/config | chỉ projection có marker |
| host MCP config | **host/máy** | provider discovery | chỉ đọc |
| `HostProfile` | **ESO DB** | assignment user×host | có |
| evidence / verdict | **ESO DB** | observatory + gate | append-only |

#### Ba mặt phẳng orchestration

| Plane | Orchestrator | SoT |
|---|---|---|
| agent loop | host / Paseo / Orca | host |
| harness projection | ESO harness adapter | `.harness` + stack |
| verdict / evidence | ESO control plane | ESO DB |

Không có một orchestrator duy nhất cho mọi thứ. Hỏi "ai orchestrate?" phải hỏi **plane nào**.

#### Host states

```text
managed     ESO adapter biết host, có projection
detected    host có marker, chưa có adapter/projection
unknown     tool không được hỗ trợ; ESO không làm gì
```

Cả ba đều hợp lệ. Host profile chỉ cần cho `managed`; `detected`/`unknown` không chặn stack.

### 0.4 Thứ tự Stack ↔ Host

- **Stack định nghĩa**: cái gì (layer, source, material, document graph).
- **HostProfile gán**: ai + host nào + pin stack version + override.
- HostProfile **reference** stack, không own stack.
- Stack **không thuộc** host; stack thuộc consumer.
- Host detection có thể xảy ra trước/sau stack, nhưng profile cần stack.
- Nếu chưa có stack: tạo draft/default trước, hoặc chặn Add host bằng CTA tạo stack.
- Add host không được hỏi lại toàn bộ stack config; chỉ hỏi host + stack binding + advanced overrides.

### 0.5 Capability policy vs capability resolution

Đây là chỗ mô hình cũ sai: Stack và Host cùng chọn source/provider.

```text
Stack                  Host Binding
capability policy      capability resolution
WHAT is required       HOW it is satisfied on this host
```

| Câu hỏi | Thuộc |
|---|---|
| Cần memory không? | **Stack** |
| Memory được phép lấy từ source nào? | **Stack** |
| Host này lấy memory từ đâu? | **Host Binding** |
| Provider cụ thể trên host này? | **Host Binding** |
| MCP config nào? | **Host Binding** |
| Document graph bật không? | **Stack** (ESO-only) |
| Material nào? | **Stack** |

Stack layer không chứa `source`/`provider` cụ thể.

```json
{
  "memory": {
    "required": true,
    "allowedSources": ["host-native", "eso-native", "market"]
  },
  "codeGraph": {
    "required": true,
    "allowedSources": ["host-native", "eso-native", "market"]
  },
  "documentGraph": {
    "required": true,
    "provider": "eso-native"
  }
}
```

Host binding mới chứa resolution:

```json
{
  "capabilityBindings": {
    "memory": { "source": "host-native", "provider": "dsh" },
    "codeGraph": { "source": "eso-native" }
  }
}
```

Không được lặp selector ở cả hai nơi.

### 0.6 Stack versioning và host pin

Stack là **versioned aggregate**, không phải singleton sửa tại chỗ.

```text
Consumer
└── HarnessStack (lineage)
      ├── v1  published  immutable
      ├── v2  published  immutable
      └── v3  draft      mutable
```

| Rule | Nội dung |
|---|---|
| Published | bất biến; sửa = tạo version mới |
| Draft | sửa được; chưa được bind |
| New binding | mặc định latest published, có thể chọn version cũ |
| Existing binding | pin version; không tự nhảy |
| Upgrade | explicit action trên binding |
| Rollback | trỏ binding về version cũ |
| Delete | không xóa published version đang được reference |
| Retire | chỉ khi không còn binding |

```text
HostBinding.stackVersion = 2
→ effective config luôn dùng v2
→ publish v3 không đổi binding
```

Nhiều binding có thể pin nhiều version khác nhau để canary/rollback.

Chi tiết mô hình và 5W1H: [Stack ↔ Host binding](../../../04.landscape/06.stack-host-binding.md).

## 1. Bối cảnh operator mô tả

Operator có repo A. Trong cùng một repo, operator muốn dùng **nhiều host cùng lúc**, không cố định 3 host:

```text
cursor · agy · dsh
```

Trong đó:

- Cursor và AGY **không có harness tích hợp đủ dùng** (vẫn có rules/skills surface; host-native chỉ partial).
- DSH có **DSH harness native**, nhưng không đủ nhu cầu; ESO bổ sung theo từng layer, không thay thế toàn bộ.
- ESO gồm **control plane observatory** + **ESO harness**.

Trong team dự án có 3 dev:

| Dev | Host dùng | Harness dùng |
|---|---|---|
| `DEV_1` | cursor + agy + dsh cùng lúc | **ESO harness** |
| `DEV_2` | cursor | **market harness** |
| `DEV_3` | cursor | **market harness** |

> Đây chỉ là **ví dụ**. Danh sách host đầy đủ của sản phẩm là:
>
> `cursor · antigravity (agy) · claude · codex · dsh · paseo · orca`
>
> Trong đó Paseo/Orca là **orchestrator**, không phải harness source. Codex là future.

Hệ quả:

- Harness không phải một lựa chọn duy nhất cho repo.
- Cùng một repo có thể có nhiều **host profile** khác nhau.
- Một số host không có harness; ESO phải cung cấp lớp bổ sung.
- Market harness là lựa chọn hợp lệ cho dev chỉ dùng Cursor.

## 3. Cơ chế cấu hình từng tầng

### 3.1 Multi-agent

Operator muốn một mô hình giống **IAM**:

```text
roles
  └── workers
        └── permissions
              └── workflows
```

- Tạo worker.
- Gán quyền.
- Quyền được điều chỉnh theo workflow.
- Đây là cấu hình **policy**, không phải copy file.

### 3.2 Rules / law · skills · hooks

Ba tầng này dùng chung cơ chế:

```text
file / folder
  → cài đặt
  → copy-paste vào folder
```

Không cần source chain phức tạp cho ba tầng này. Cần biết:

- file/folder nào thuộc consumer;
- đã cài vào host nào;
- host nào không hỗ trợ.

### 3.3 Memory

Nguồn hợp lệ:

```text
eso-native memory
host-native memory        # ví dụ DSH
market memory             # agentmemory, ...
```

Market provider đọc từ:

```text
mcp.json
mcp_config.json
```

trong repo để biết người dùng muốn dùng provider nào.

### 3.3b MCP config

MCP là **config từ máy**, không phải layer canonical trong repo.

Nguồn cấu hình:

```text
mcp.json              # Cursor
mcp_config.json       # Antigravity
plugin config         # DSH / Paseo / Orca
```

Host profile phải ghi nhận:

- file MCP nào đang dùng;
- provider nào được bật;
- plugin nào cung cấp MCP;
- config đó là máy-local hay được sync.

Không được giả định `mcp.json` là nguồn duy nhất.

### 3.4 Code graph

Cùng mô hình source như memory:

```text
eso-native code graph
host-native code graph
market code graph          # codegraph, ...
```

### 3.5 Document graph / docgraph

- Từ nay gọi thống nhất: **document graph**; `docgraph` là tên viết tắt của document graph.
- Là **USP của ESO**.
- Market hiện không có.
- Host hiện không có.
- Cần **advanced config riêng**.
- Liên quan PostgreSQL; đã có mô tả từ trước.
- Nếu Jira được bật, document graph đi kèm:
  - sync SDLC Jira;
  - manifest document.

### 3.6 Topology

Operator chưa có ý kiến. Không được tự mở scope.

## 4. Mô hình nhiều host / nhiều dev

```text

│   ├── hooks
```

Mỗi host profile có thể chọn:

```text

market provider

```

Canonical harness là **một**. Host profile là **nhiều**.

## 5. Jira

Jira **không bắt buộc**.

Nếu operator bật:

```text
jira.enabled = true
  → document-graph settings
  → sync SDLC Jira
  → manifest document
```

Nếu tắt:

```text
không có document-graph sync
không có Jira manifest
```

## 7. Ma trận cần dùng

### 7.1 Host × capability

| Host | Nhóm | Rules | Skills | Subagents | Hooks | MCP | Host-native harness | Trạng thái |
|---|---|---|---|---|---|---|---|---|
| **Cursor** | IDE-native | `.cursor/rules/*.mdc` | `.cursor/skills` | `.cursor/agents` | `.cursor/hooks.json` | `.cursor/mcp.json` | partial | using |
| **Antigravity** | IDE-native | `.agents/rules/*.md` | `.agents/skills` | `.agents/agents` | chưa xác định | `.agents/mcp_config.json` | partial | using |
| **Claude** | CLI-native | `CLAUDE.md` + import | `.claude/skills` | `.claude/agents` | `.claude/settings.json` | chưa đo | partial | using |
| **Codex** | CLI-native | — | — | — | — | — | future | future |
| **DSH** | plugin-runtime | `AGENTS.local.md` | `.agents/skills` | không discovery | plugin `.claude/hooks.json` | profile rows | **strong** | using |
| **Paseo** | orchestrator | — | — | — | — | qua agent con | **không phải source** | future |
| **Orca** | orchestrator | — | — | — | — | qua agent con | **không phải source** | future |

Host-native là **capability level**, không phải tên host. Mỗi host là một **plugin adapter**; bảng này là registry hiện tại, không phải danh sách hardcode. Cursor/AGY/Claude là `partial`; DSH `strong`;
Paseo/Orca chỉ orchestrate; không phải host-native source. Codex chưa đo.

| Document graph | **USP** | không | không | — | advanced/Postgres |
| Topology | có | không | graphify | — | defer |

## 7.3 Không có tier / edition

- Chỉ có **một sản phẩm**.
- Không có `Lite` / `Pro` / `DSH-native` / `community` / `team` / `enterprise`.
- `tier` nếu xuất hiện chỉ có thể là **capability level** (`strong`/`partial`/`future`), không phải product edition.

## 7.4 Document graph ≠ docgraph

- `docgraph` = **document graph**.
- ESO document graph trả lời "điều này đã được biết chưa": `doc → section → id`, specific-relative.
- Đây là **USP của ESO**.
- Runtime graph: PostgreSQL `graph`; code graph + document graph dùng cùng engine (`D-73`).
- Không dựng lại search engine; search vẫn mượn provider (`D-26`).
