Architecture Reference · SDLC Knowledge Governance

Doc-Driven vs. Spec-Driven & Artifact Governance

Root cause analysis, SDLC symmetry axis, 3 artifact categories, and closed feedback loop in agentic software engineering.

1. Root Cause: The Ambiguity Trap in AI Workflows

In traditional human engineering, Document-Driven development (PRDs, ADRs, RFCs) works well because human engineers intuitively resolve ambiguities, ask clarifying questions, and adapt to unwritten business context.

Why it breaks with AI agents: Autonomous AI agents cannot infer unstated constraints. When given free-form prose without strict machine boundaries, agents speculate on missing data types, invent ungrounded schemas, and drift away from architectural intent (“vibe coding”). Natural language prose cannot be verified by automated CI gates or deterministic test runners.

2. The Rigidity Trap: Premature Spec-Driven in Early Inception

Specification-Driven methodologies (OpenAPI schemas, JSON Schemas, Protobuf, strict TDD Acceptance Criteria) guarantee 100% deterministic verification (PASS/FAIL).

Why it breaks in early phases: Mandating strict formal schemas during early discovery, spikes, and brainstorming creates immense friction. If requirements pivot, maintaining rigid schemas wastes engineering effort. Crucially, schemas specify “What” (inputs/outputs), but completely omit “Why” (business rationale, discarded alternatives, and trade-offs).

The 6 Knowledge Sub-Tabs Across the Continuum:
1. Overview Preflight & Readiness

Preflight checks (01..03) ensuring links resolve, derived sources labelled, and boundaries respected.

2. Sources Repository Sources (sdlc/)

Maps canonical markdown source documents. Files are the source of truth; providers are optional.

3. Contract Integrity Rules (X1–X42)

Enforces semantic integrity, cross-layer trace links (PRD → Spec → Code), and governance standards (G1–G16).

4. Index & Health Doc Graph & Embeddings

Extracts document vertices, dependency edges, vector embeddings, and reports open findings.

5. Manifest Machine Contract (SHA-256)

Generates knowledge-manifest.json with cryptographic hashes for immutable AI agent contracts.

6. Artifacts Inbox & Host Projections

Staging ground for Category 2 research drafts (raw → proposed) and Category 1 zero-drift runtime projections.

  • The Phase-Transition Hinge (06.analysis): Acceptance Criteria (AC / Gherkin) serve as the unique pivot translating human story narrative into machine-verifiable assertions.
  • The Mandatory Boundary Guard (08.wbs): Work breakdown slicing with locked allowed_files constrains agent blast radius before code implementation starts.
  • The Closed Feedback Loop: When 10.test / code fails or contract linters detect inconsistencies, knowledge routes back to 06.analysis or 03.inception for revision prior to release.

5. The Three Artifact Categories in ESO

Category 1: Host Projections
Machine-generated configurations (.agents/, .cursor/, AGENTS.local.md) projected from canonical source to guarantee zero-drift across IDE runtimes.
Category 2: Working Artifacts
Living research spikes, deep dives, and draft RFCs created in human-agent sessions, staged in the Inbox through states: raw → proposed → approved → retired.
Category 3: Formal Contracts
Approved specifications locked by SHA-256 hash in knowledge-manifest.json and indexed into vector RAG embeddings for all AI agents.

6. System Pathologies & Governance Guardrails

  • Artifact Pollution: Prevented by Gate S17 human review; autonomous AI agents are strictly prohibited from self-promoting unverified claims into production.
  • Split-Brain Custodianship: Enforced by Single Source of Truth; staging lives in the database while approved contracts reside immutably in the Git repository.
  • Phantom Drift: Prevented by generator checks (build-host-trees.mjs --check); hand-editing host projection trees is blocked.
